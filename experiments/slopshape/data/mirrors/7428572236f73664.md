# What's New in Git 1.8.4: The Highlights You'll Actually Use

Confession time: I read release notes for fun. When a new git version drops, I'm the one scrolling through the changelog with a cup of coffee, muttering "oh, nice" at my screen. Git 1.8.4 is out, and there's plenty in it worth getting excited about. Rather than walk you through every line of the changelog, here's my opinionated tour of the stuff that'll make your day-to-day life better.

## First, Upgrade!

Getting the new version is quick:

- **Homebrew (OS X):** `brew update && brew upgrade git`
- **Ubuntu:** The default repositories tend to lag behind, so grab the Git maintainers' PPA: `sudo add-apt-repository ppa:git-core/ppa`, then `sudo apt-get update && sudo apt-get install git`
- **Windows:** Download the latest installer from the msysgit project page once the 1.8.4 build is available.

Run `git --version` to confirm, and let's dig in.

## Submodules Get a Little Less Painful

Submodules have a reputation, and it's not entirely undeserved. But 1.8.4 smooths out some rough edges. You can now run `git submodule update` and friends from a subdirectory of your project rather than having to `cd` back to the top level first. Small change, big quality-of-life win.

Even better, `git mv` now understands submodules. Move a submodule directory and git updates the `.gitmodules` file and the submodule's internal pointers for you. No more hand-editing config files and hoping you got it right. Similarly, `git submodule deinit` lets you cleanly unregister a submodule without the usual ritual of deleting things in three different places.

## Rebase Grows Up: Autostash and Better Options

This is my favorite part of the release. How many times have you tried to rebase, only for git to tell you your working tree is dirty? You sigh, stash, rebase, pop. Every. Single. Time.

Now there's `rebase.autostash`. Set it with:

```
git config --global rebase.autostash true
```

Git will automatically stash your local changes before the rebase and reapply them afterward. It's the kind of feature that makes you wonder how you ever lived without it.

Rebase also got better at handling options. Interactive and non-interactive rebases now accept a more consistent set of flags, and `git rebase` gained support for passing merge-strategy options more smoothly. Fewer "wait, does this flag work here?" moments.

## Status, Log, and Diff Get New Tricks

A handful of configuration and ordering options landed across the everyday commands:

- **`status.branch` and `status.short`**: If you always type `git status -sb` (like I do), you can now make that the default. Set `status.short` and `status.branch` to `true` and enjoy the compact view permanently.
- **`log --author-date-order`**: Want your history ordered by when work was authored rather than when it was committed? Now you can have it, while still showing parents before children.
- **`diff.orderfile`** and `-O`: You can specify the order in which files appear in diffs. Put the interesting stuff, like your source files, before the noise, like generated files or lockfiles. Great for reviewing larger changes.

## Color by Default (Finally!)

Here's a friendly one: starting with 1.8.4, `color.ui` defaults to `auto`. That means colored output out of the box in your terminal, no config needed. If you've been setting this on every new machine for years, you can finally drop that line from your setup scripts. New users get a much friendlier first experience too.

## The Grab Bag

A few smaller additions that deserve a shout-out:

- **`git config --get-urlmatch`** lets you set configuration per URL pattern, which is handy for HTTP settings that differ between hosts.
- **`git check-mailmap`** shows you how a name and email would be mapped through your `.mailmap` file.
- **`@` as a shortcut for `HEAD`**: Type `git log @~3` instead of `git log HEAD~3`. Lazy? Yes. Delightful? Also yes.
- **`git fetch` and `git push`** got better messages and behavior around tag handling and refspecs.
- **`git commit --fixup`** workflows play even nicer with `rebase --autosquash`.

Speaking of those fixup and autosquash workflows: if your team uses them, there's an Atlassian Stash add-on that helps you spot and manage fixup commits right in your pull requests, so reviewers can see what's getting squashed before it lands. It pairs really nicely with the improved rebase behavior in this release.
