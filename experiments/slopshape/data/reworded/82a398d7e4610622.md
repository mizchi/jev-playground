# Database Interview Questions Every Data Scientist, Data Engineer, and Software Engineer Should Know

Nearly every technical role today works with data. Data scientists query warehouses for analysis, data engineers design pipelines, and software engineers build application backends, and all of them have to show they understand how databases work. As a result, database questions come up often in technical interviews.

This guide covers what a typical database interview looks like, the concepts and technologies you should know, and a set of original practice problems sorted by difficulty. Treat it as a study guide while you prepare for your next technical screen.

## What Is a Database Interview?

A database interview tests how well you design, query, and reason about data storage systems. Depending on the role, it may be its own round or part of a wider technical assessment.

Most database interviews mix some of the following:

- **Concept questions** on theory, such as normalization or indexing.
- **Coding exercises** in which you write SQL queries or code that talks to a database.
- **Design discussions** in which you model a schema for a real-world scenario.

Many companies now run these interviews in a collaborative IDE, so you and the interviewer see the same code in real time. You usually get a schema, sample data, and a problem statement, and you are expected to write a working solution and explain your reasoning as you go.

## Key Concepts and Technologies to Review

Before you begin practice problems, check that you are comfortable with these core topics.

### Relational Database Fundamentals

- **Tables, rows, and columns**, and how primary and foreign keys connect tables.
- **Normalization**: organizing data to reduce redundancy. Know the first three normal forms (1NF, 2NF, 3NF) and when denormalizing is the better choice.
- **Joins**: inner, left, right, full outer, cross, and self joins.
- **Indexes**: how they speed up reads, what they cost on writes, and when to use composite indexes.
- **Transactions and ACID properties**: atomicity, consistency, isolation, and durability.

### SQL

- Filtering, sorting, and aggregation (`WHERE`, `ORDER BY`, `GROUP BY`, `HAVING`)
- Subqueries and common table expressions (CTEs)
- Window functions (`ROW_NUMBER`, `RANK`, `LAG`, `LEAD`, running totals)
- Handling `NULL` values

### NoSQL

- The major categories: document stores (MongoDB), key-value stores (Redis), wide-column stores (Cassandra), and graph databases (Neo4j).
- Trade-offs between consistency, availability, and partition tolerance (the CAP theorem).
- When a NoSQL solution suits a problem better than a relational database.

### Big Data Processing

- **MapReduce**: a programming model that processes large datasets in parallel by mapping input into key-value pairs and reducing those pairs into aggregated results.
- For data engineering roles, familiarity with distributed frameworks such as Hadoop and Spark helps.

## Sample Database Interview Questions

The original problems below fall into three tiers. Work through them somewhere you can actually run your queries.

### Tier 1: Multiple-Choice Concept Checks

These questions check your grasp of foundational ideas.

**Question 1:** A table stores `order_id`, `customer_id`, `customer_email`, and `order_total`. Each customer's email appears in every one of their orders. Which normal form does this design violate?

A. First normal form
B. Second normal form
C. Third normal form
D. It doesn't violate any normal form

*Answer: C.* `customer_email` depends on `customer_id` rather than on the primary key `order_id`. That transitive dependency violates 3NF.

**Question 2:** Which join returns all rows from the left table, along with matching rows from the right table, filling unmatched columns with `NULL`?

A. INNER JOIN
B. LEFT JOIN
C. CROSS JOIN
D. SELF JOIN

*Answer: B.*

**Question 3:** A social network wants to quickly find friends-of-friends for millions of users. Which database type is most naturally suited to this workload?

A. Key-value store
B. Relational database
C. Graph database
D. Columnar data warehouse

*Answer: C.* Graph databases are built for traversing relationships.

**Question 4:** In a MapReduce word-count job, what does the reduce step typically do?

A. Splits text into individual words
B. Emits a key-value pair for each word
C. Sums the counts for each unique word
D. Sorts the input files alphabetically

*Answer: C.*

### Tier 2: Basic Coding Exercises

Each of these problems targets one concept and should take only a few minutes.

**Problem 1: Active Library Members**

A table `loans` has columns `member_id`, `book_id`, and `loan_date`. Write a query that returns the `member_id` of each member who borrowed at least five books in 2024.

```sql
SELECT member_id
FROM loans
WHERE loan_date >= '2024-01-01'
  AND loan_date < '2025-01-01'
GROUP BY member_id
HAVING COUNT(*) >= 5;
```

**Problem 2: Products Never Ordered**

Given `products(product_id, name)` and `order_items(order_id, product_id, quantity)`, return the names of products that no one has ever ordered.

```sql
SELECT p.name
FROM products p
LEFT JOIN order_items oi ON p.product_id = oi.product_id
WHERE oi.product_id IS NULL;
```

**Problem 3: Average Rating by Category**

Given `recipes(recipe_id, category)` and `reviews(recipe_id, rating)`, return each category with its average rating, sorted from highest to lowest.

```sql
SELECT r.category, AVG(v.rating) AS avg_rating
FROM recipes r
JOIN reviews v ON r.recipe_id = v.recipe_id
GROUP BY r.category
ORDER BY avg_rating DESC;
```

### Tier 3: Advanced Challenges

These problems ask you to combine several concepts or draw on deeper SQL knowledge or language-specific skills.

**Problem 1: Top Earner per Department**

Given `employees(employee_id, name, department_id, salary)`, return the highest-paid employee in each department. When employees tie, return all of them.

```sql
WITH ranked AS (
  SELECT name, department_id, salary,
         RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rnk
  FROM employees
)
SELECT name, department_id, salary
FROM ranked
WHERE rnk = 1;
```

**Problem 2: Consecutive Login Streaks**

Given `logins(user_id, login_date)` with one row per user per day, find the users who logged in on at least three consecutive days.

```sql
WITH grouped AS (
  SELECT user_id, login_date,
         login_date - (ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date)) * INTERVAL '1 day' AS grp
  FROM logins
)
SELECT DISTINCT user_id
FROM grouped
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

The query relies on the "gaps and islands" technique: subtracting each date's row number from a run of consecutive dates yields the same group value.

**Problem 3: Month-over-Month Revenue Change**

Given `sales(sale_date, amount)`, return total revenue for each month and its percentage change from the month before.

```sql
WITH monthly AS (
  SELECT DATE_TRUNC('month', sale_date) AS month, SUM(amount) AS revenue
  FROM sales
  GROUP BY 1
)
SELECT month, revenue,
       ROUND(100.0 * (revenue - LAG(revenue) OVER (ORDER BY month))
             / LAG(revenue) OVER (ORDER BY month), 2) AS pct_change
FROM monthly
ORDER BY month;
```

**Problem 4: Aggregating Documents in Python**

You have a list of JSON-like documents representing sensor readings, each containing `sensor_id` and `temperature`. In Python, write a simple map step and reduce step that compute the maximum temperature for each sensor.

```python
from collections import defaultdict

def map_step(readings):
    for r in readings:
        yield r["sensor_id"], r["temperature"]

def reduce_step(pairs):
    result = defaultdict(lambda: float("-inf"))
    for sensor_id, temp in pairs:
        result[sensor_id] = max(result[sensor_id], temp)
    return dict(result)

max_temps = reduce_step(map_step(readings))
```

## Tips for Your Database Interview

- **Clarify the schema first.** Before writing code, ask about data types, nulls, and duplicates.
- **Talk through your approach.** Interviewers weigh your reasoning as heavily as your final answer.
- **Test with edge cases.** Check how your solution handles empty tables, ties, and missing values.
- **Think about performance.** Bring up indexes or query plans where they apply.
