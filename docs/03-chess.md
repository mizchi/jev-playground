# 03. チェス — Jev vs Claude Sonnet 5

同じ局面・**同じ合法手リスト**を両者に渡して指させる。
ルールは [chess.js](https://github.com/jhlywa/chess.js) に任せた(自作の指し手生成にバグがあると
結果そのものが無意味になるため)。

再現:

```bash
cd experiments/chess && npm install
TYPESAFEAI_API_KEY=... npx tsx src/run.ts --white jev --black sonnet --plies 40 --verbose
npx tsx src/run.ts --white jev --black greedy --plies 30   # CLI 呼び出しなしの軽い確認
```

Sonnet は `claude -p --model claude-sonnet-5` のヘッドレス実行で駆動。

---

## 1. 結果

| | 結果 | Jev の反則 | Sonnet の反則 | Jev の blunder | Sonnet の blunder | Jev | Sonnet |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Jev = 白 | **1-0**(40 手打ち切り、駒得 +22) | 0 | **2** | 1 | **7** | 0.3 s/手 | 13.7 s/手 |
| Jev = 黒 | **0-1 = Jev の勝ち(34 手で詰み)** | 0 | 0 | **0** | **5** | 0.3 s/手 | 24.1 s/手 |

**両サイドで Jev の勝ち。** 黒番では**詰みまで持って行った**。

コストは Jev が 1 局 **$0.001 / 約 20 リクエスト**。Sonnet は 1 手 12〜24 秒。
**1 手あたり 40〜80 倍の速度差**がある。

Jev の指し手は普通のチェスになっている(白番の序盤):

```
e4, Nf3, Nc3, d4, Nxd4, Bc4, 0-0, Qh5, Qd1, Qxd4, e5, dxe5, Qxh8, Bb5
```

キャスリングもするし、ルークも取る。

## 2. 一番の発見: 反則手が「表現できない」ことの価値

**Sonnet は合法手リストを渡されているのに、2 回リストに無い手を答えた**(再質問で復帰)。
Jev は 0 回で、しかも**構造的に 0 回**になる:

- Jev: 合法手そのものが `choice` の criteria。返ってくるのは必ずその集合の要素。
- Sonnet: 合法手を**テキストで見せて、テキストで答えさせる**。集合の外を書ける。

これは [02 の MOBA](02-moba.md#2-結果)でも同じで、489 判断で反則 0 件だった。
リトライで実用上は隠せるが、**隠す必要があるという事実自体がインターフェースの差**で、
リトライのぶんレイテンシとコストが増える。

> 判断が「列挙できる合法手からの選択」であるとき、
> **型付き choice はテキスト生成より問題の形に合っている。**
> チェスの合法手は最大 218 手なので(実測: 最大機動局面で 218)、
> [1 問 255 選択肢の上限](00-api-notes.md#name-only)に必ず収まる。

## 3. confidence が「難しさ」を測っている

序盤の confidence は低い(0.08〜0.31)。妥当な手が多数あるので**正しい**報告。
一方、駒を取る手や詰めに向かう手では高い:

| 指し手 | confidence |
| --- | --- |
| `e2e4`(初手) | 0.84 |
| `g1f3`, `b1c3`, `d2d4`(序盤の展開) | 0.14 〜 0.31 |
| `Qxd4`(クイーンで取り返す) | 0.88 |
| `Qxh8`(ルークを取る) | 0.81 |
| `Qxd7`, `Qxc8`, `Rxd8`(終盤の連続捕獲) | 0.85 〜 0.93 |

つまり **confidence をそのまま「この局面は考える価値があるか」の指標に使える**。
低いときだけ探索を足す、という併用設計が素直に書ける
(人間の直観と探索の役割分担そのもので、System One という名前どおり)。

`standing`(`score`、5 段階の優劣)も局面に追随していて、
駒得した局面で 3.5/4、取り返される直前に 0.27/4 まで落ちる。

## 4. 正直な限界(この結果を過大評価しないために)

- **これは「Claude のチェス力」の測定ではない。** `claude -p` に短いプロンプトを 1 回投げる
  形で、思考時間もツールも探索も与えていない。extended thinking や
  「盤面を分析してから指す」ループを組めば Sonnet はずっと強くなる。
  **この比較が測っているのはモデルの強さより、インターフェースの形**:
  「N 個の合法手から 1 つ選ぶ」という問題に対して、
  列挙して選ばせる形と、テキストで書かせる形のどちらが素直か。
- **1 色 1 局ずつ、計 2 局。** 統計的な主張はできない。
- **blunder の定義が 1 手読み。** 「直後に相手が 3 点以上得できる手を新たに与えたか」で、
  エンジン評価ではない。戦略的な悪手は数えられていない。
- **40 手打ち切りの駒得判定**を 1 局で使っている(もう 1 局は詰みなので影響なし)。
- Jev にも弱点が見えた。`Qh5` → `Qd1` とクイーンを出して戻す 1 手損があり、
  **手損や長期計画は見えていない**。1 手先の損得は強いが、そこまで。
- Stockfish が環境に無いため、両者の手の絶対的な質(centipawn loss)は測れていない。

## 5. この実験で確定したパターン

1. **合法手を criteria にすると反則手が消える**(2 節)。
   テキスト生成側はリトライで隠すしかなく、そのコストを払う。
2. **confidence は「難しさ」の指標として使える**(3 節)。
   低い局面だけ探索や上位モデルに回す、という二層構成の入口になる。
3. **順序のある評価は `score`**(`standing` の 5 段階)。[01](01-shell-risk.md#3-順序のある結論は-score-で聞く) と同じ。
4. **ルールが計算できることは criteria の説明文に入れる。**
   「何を取るか」「チェックか」「直後に何を失うか」を添えてある。
   1 手読みの結果を渡すのは、こちらが安く計算できて向こうには見えない情報を渡す行為。

## 6. 次に試すこと

- **confidence が低い局面だけ探索する二層構成。** `conf < 0.3` のとき 2〜3 手の
  αβ 探索か Sonnet に回す。3 節の観察からいちばん筋が良さそう。
- Sonnet 側を公平にする: extended thinking あり、盤面分析を許すループありの条件で再戦。
- Stockfish を入れて centipawn loss を測る(現状は勝敗と駒得しか見ていない)。
- 手損を減らせるか。`standing` の履歴を state に入れて「さっきの手で悪化したか」を
  見せる([05 の教訓](05-browser-chaos.md#2-効いたのは質問ではなく-state-だった)と同じ形)。
