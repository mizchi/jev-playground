# 66. SlopShape の追試 —— 論文の「形」は Jev でも読めた。判定機にするなら、文脈は文章ではなく質問にして渡す

[SlopShape](https://arxiv.org/abs/2609.15369)(Madler, 2026、arXiv:2609.15369)は、
**AI が書いた企業ブログは「構造」だけで見分けられる**という論文です。
言い回し(style)ではなく、**何をどの順で、どんな根拠で、どんな声で言うか**を 214 個の特徴として LLM に採点させ、
その答えだけで分類器を作ると **macro-F1 98.0**、AI 側を自分自身で言い換えさせても **98.1** のまま。
しかも「AI の形」を**10 個の核(core)の値**で言えて、それが「整っていて、自分で予告する記事」になる:
タイトルで効用を約束し、最初の節の前に主張と流れを予告し、論説調で説明し、最後に要約で閉じる。

この報告は 2 つの問いに答えます。

1. **追試。** 論文の測定器(214 特徴・正規化・核の値の向き)を**リリースからそのまま**使い、
   採点者だけを Jev に替えて、同じ現象が出るか。
2. **判定機。** Jev に論文の知見を**文脈として**渡せば、学習なしで「AI が書いたか」の判定機になるか。

| | 何を測るか | n | 結論 |
| --- | --- | --- | --- |
| [§1](#what-changed) | 何を変えたか(逸脱の台帳) | — | 採点者・AI 源・人間記事の取り方の 3 つが主な違い |
| [§2](#instrument) | **Jev を採点者にした論文のパイプライン** | 55 組 × 307 問 | 構造特徴で **AUC 0.88**(確率を使うと **0.93**)、**繰り返し一致 κ 0.970**(論文 α 0.891) |
| [§3](#directions) | **核 10 値の向きは再現するか** | 55 組 | **10/10 が論文と同じ向き** |
| [§4](#title) | **リリースの人間記事にはタイトルが無い** | 55 組 × 2 | 核の 1 つ「タイトルで効用を約束」は**タイトルを戻すと向きが逆になる** |
| [§5](#reword) | 言い換え攻撃 | 55 本 | 構造 **0.782 → 0.782**・style **0.627 → 0.581**。論文と同じ形 |
| [§6](#rarity) | 人間は稀な構造に居るか | 110 本 | **向きは再現、大きさは 5 分の 1**(d 0.39 対 1.83) |
| [§7](#judge) | **Jev に文脈を渡して判定機にする** | 55 組 × 3 腕 | 文章で渡すと **AUC 0.63〜0.68 で文脈は効かない**。**同じ 10 値を質問に分けると学習なしで 0.79** |
| [§8](#recent) | **2023 年以降の人間記事で誤検出はどこまで増えるか** | 29 社・102 本 | 構造で判定する腕は**ほぼ増えない**(誤検出 10% に合わせた閾値で 2023+ の検出率 9〜16%)。**丸ごと聞く腕は 27〜29% に増え、AI より「新しさ」を見分けている** |
| [§9](#suspect) | **使うための 1 本** | — | `src/suspect.ts`: 記事ファイル → 疑わしさ・人間記事の中での位置・押し上げた値 5 つ |

**結論を 1 行で: 論文の現象は採点者を Jev に替えても向きがすべて再現し、ただし核の 1 つはリリースの前処理の非対称(人間側だけタイトルが無い)で説明できました。
判定機としては、論文の知見を instructions に文章で書いても効かず(AUC 0.63〜0.68)、
同じ知見を 10 個の型付き質問に分けて足すだけで、学習なしで AUC 0.79 になります。
そして同じ会社の 2023 年以降の記事では、構造で判定する腕の検出率は 9〜16% に留まり(2022 年以前の人間で 9% の閾値)、丸ごと聞く腕は 27〜29% に跳ねます。**

再現:

npm test                             # 18 件(正規化がリリースの Python と全文一致、など)。API 不要

生成(ブリーフ・AI 記事・言い換え)は Claude Code のサブエージェントに、プロンプトファイルだけを読ませて書かせました(§1)。

## 1. 何を変えたか

論文は自分の逸脱を D1〜D16 の台帳にしています。同じ形で、こちらの逸脱を L1〜L8 に並べます。
**測定器そのもの(特徴の定義・答えの選択肢・除外・style の境界・核の値とその向き・正規化)は 1 つも変えていません** ——
全部リリースの固定コミット(`6c1fbd0`)から実行時に読み、`scripts/release.sh` が MANIFEST の sha256 と照合します。
リリースは code 以外が all rights reserved なので、**リポジトリには 1 ファイルも複製していません**。

| # | 論文 | ここ | なぜ / 何が起きうるか |
| --- | --- | --- | --- |
| L1 | 人間記事は Wayback のスナップショット | **live URL** を取り、trafilatura 2.2.0(リリースと同じ版)で抽出。**語数がマニフェストの ±10% 以内、タイトルの語が 6 割以上一致**したものだけ残す | この環境のネットワーク方針が web.archive.org を通さない。**公開後に書き換えられた記事を完全には弾けない**(残った 55 本の語数差は平均 2.6%) |
| L2 | AI 源 5 つ(gpt-5.4・claude-sonnet-4.6・gemini-3-flash・deepseek-v3.2・kimi-k2.5)、人間 1 : AI 5 | **AI 源 1 つ**(Claude Code のサブエージェント)、**1 : 1** | 生成モデルの API キーが無い。**6 者の帰属(論文 §5.5)は測れない** |
| L3 | ブリーフは gemini-3-flash | ブリーフも同じサブエージェント(人間記事を読むのはブリーフ係だけ、AI 記事係はブリーフだけを読む) | 同上。**プロンプトは逐語**(`study_b/extract_briefs.py` の `BRIEF_PROMPT` を実行時に抜き出す) |
| L4 | 採点者は gemini-3.6-flash、次元ごとに JSON で 11 回 | **Jev**、特徴ごとに型付き質問、**1 記事 1 リクエスト**(307 問) | これが追試の本題。答えの形は特徴の型に合わせた(§2) |
| L5 | XGBoost、ドメインで 198/32/38 に分割、格子探索 | **L2 ロジスティック回帰**(λ = 10、**結果を見る前に固定**)、**会社ごとに 1 つ抜く**交差検証(33 社) | 55 組では格子探索する検証集合が作れない |
| L6 | 言い換えは各モデルが自分の記事を、クレーム保存の判定を全数 | 同じ書き手が LAMP プロンプト(リリースの `prompts/lamp_rewrite.md`)で。**長さと丸写しのゲートだけ** | クレーム保存の全数判定はしていない |
| L7 | 人手の gold 注釈(κ 0.928 / 0.946) | **無し**。代わりに繰り返し一致(§2.1) | 人手が居ない。**「Jev が人間の読みと一致するか」は測っていない** |
| L8 | 単発生成 | 55 本中 **3 本は書き手が長さ合わせで手を入れた** | 書き手の報告で判明。[`records/generation_notes.json`](../experiments/slopshape/records/generation_notes.json) に記録し、`--single-pass-only` で除いた数字も出す(§2) |

**人間記事の標本。** リリースの凍結された分割で **val と test のドメインだけ**から(論文の分類器を訓練していない会社)、
種子つきで並べ、1 社 2 本まで。候補 365 本のうち **取れなかった 176・語数が合わない 119・タイトルが合わない 15**、残り **55 本・33 社**。
台帳は [`records/human_ledger.csv`](../experiments/slopshape/records/human_ledger.csv)(本文は含まない)。

**正規化はリリースと全文一致。** AI は markdown を書き、HTML から抜いた人間記事には印が無いので、
論文は両側から markdown と飾り行を剥がしています(`study_b/normalize.py`)。
それを TypeScript に移し、**テストが Python の原本を全 165 本に走らせてバイト単位で一致を要求**します。

**生成の衛生。** ブリーフが人間記事と 13 語連続で一致するものは **0/55**、AI 記事は **1/55** ——
一致した 1 件は FDA の定義文(「expected to produce the same clinical result as the reference product」)でした。

<a id="instrument"></a>

## 2. Jev を採点者にした論文のパイプライン

214 特徴を、**型ごとに Jev の答えの形へ**写しました([tuning §1](tuning.md) の「答えの形を先に決める」):

| 特徴の型 | 数 | Jev の質問 | 符号化(リリースの `r6_build.py` と同じ列) |
| --- | --- | --- | --- |
| binary・categorical | 150 | `choice`(選択肢 = 許された値) | one-hot |
| ordinal・scale | 51 | **`score`**(選択肢を順に) | 位置(0, 1, …) |
| multi_select | 13 | **値ごとに `noul`**(106 問) | multi-hot |

instructions は特徴の `question` と `detection_method` だけ。**誰が書いたかに触れる語は 1 つも無い**(テストで固定)。
state は「B2B の企業ブログ。テキストにあることだけで判断する」の 1 文と、正規化した本文(先頭 2,600 語、リリースと同じ)。
符号化は**リリースと同じ 868 列**になります(テストで固定)。

### 2.1 繰り返し一致は論文の採点者より高い

最初の 10 組(人間・AI の 20 本)を**あと 2 回**採点し直すと、単一回答の 8,040 項目で
**完全一致 0.970・κ 0.970**。論文は gemini で 60 本 × 5 回、**Krippendorff α 0.891**(基準 0.8)でした。
**測定器として Jev は再現性で劣らない。**(ただし人間の読みと一致するかは測っていない —— L7)

### 2.2 検出

会社ごとに 1 つ抜いて学習し、抜いた会社の記事を当てます。
セルは **macro-F1 [95% CI] / AUC [95% CI] / 対(同じブリーフの AI 記事が、元の人間記事より AI らしいと出た割合)**。
CI は論文と同じく**会社ごとに**リサンプリング(2,000 回)。

| 変種 | そのまま | 言い換え後 | 論文 macro-F1 |
| --- | --- | --- | --- |
| **構造(187)** | **0.782** [0.698, 0.858] / **0.878** [0.823, 0.930] / 0.982 | 0.782 [0.700, 0.853] / 0.867 [0.805, 0.926] / 0.964 | 0.980 |
| style だけ(27) | 0.627 [0.556, 0.698] / 0.692 [0.625, 0.763] / 0.782 | 0.581 [0.509, 0.644] / 0.670 [0.604, 0.741] / 0.764 | 0.881 |
| 全部(214) | 0.800 [0.724, 0.870] / 0.901 [0.851, 0.949] / 0.982 | 0.818 [0.743, 0.886] / 0.887 [0.829, 0.942] / 0.964 | 0.981 |
| 核だけ(10) | 0.736 [0.657, 0.815] / 0.832 [0.758, 0.902] / 0.873 | 0.782 [0.696, 0.862] / 0.835 [0.754, 0.909] / 0.873 | 0.935 |
| **構造、確率で符号化** | **0.882** [0.821, 0.935] / **0.929** [0.873, 0.973] / 0.982 | | |
| 語数だけ | | | AUC **0.537** |

読み方:

- **論文の順序はそのまま出ます** —— 全部 ≥ 構造 > 核 > style、そして**構造は style に 0.155 勝つ**(論文 0.099)。
  論文の第 1 仮説「商用文なら style の方が効くはず」は、**ここでも逆**でした。
- **大きさは論文より小さい**(0.782 対 0.980)。55 組と 1,566 組、ロジスティックと XGBoost、AI 源 1 つと 5 つ —— **どれが効いているかは分離していません**。
  ただし**対の 0.982** は「同じブリーフから書かれた 2 本なら、ほぼ必ず AI の方を AI らしいと言う」ことで、
  取りこぼしの大半は**会社をまたいだ閾値**の方にあります。
- **確率で符号化すると 0.878 → 0.929。** 論文の符号化は答えを 1 つに潰しますが、Jev は選択肢ごとの確率を返すので、
  **潰さない方が情報が残る**。これは Jev を採点者にしたときに初めて取れる手です。
- **語数だけでは分からない**(AUC 0.537)。論文(45.5 F1)と同じく、長さは信号ではない。
- **書き手が手を入れた 3 組を除いても**構造 0.798 / AUC 0.898 で、結論は変わりません。

## 3. 核 10 値の向きは、10 個とも再現する

論文の表 6 は「この値は人間寄り / AI 寄り」を 10 個挙げます。
その向きを**リリースの `core_values_selection.json` から**読み、Jev の答えで人間と AI の平均を比べました。

| 値 | 論文の向き(差) | 人間 / AI(ここ) | 一致 |
| --- | --- | --- | --- |
| 結びで主張を言い直す(STR_STG_008) | AI(0.650) | 0.073 / 0.200 | ✅ |
| **タイトルで効用を約束(PUR_OUT_003)** | AI(0.624) | 0.200 / 0.545 | ✅(§4 を見てください) |
| 要約・総括の段がある(STR_STG_001) | AI(0.609) | 0.673 / 0.909 | ✅ |
| 外への参加経路が無い(VOC_PRT_005) | AI(0.592) | 0.473 / 0.673 | ✅ |
| 旧来と現代の対比が無い(STR_FLW_005) | 人間(0.497) | 0.727 / 0.545 | ✅ |
| 最初の単位の前に主張が無い(STR_FLW_006) | 人間(0.419) | 0.436 / 0.145 | ✅ |
| 賭け金が上がっていかない(AUD_STK_005) | 人間(0.362) | 0.655 / 0.509 | ✅ |
| 論説調の説明者の声(VOC_VOX_001) | AI(0.308) | 0.236 / 0.364 | ✅ |
| 800 語未満(PAG_FUR_011) | 人間(0.274) | 0.091 / 0.018 | ✅ |
| 問題が明示される位置が遅い(AUD_PRB_002、順序) | 人間(0.222) | 0.586 / 0.518 | ✅ |

**10/10。** 採点者が違い(Jev)、AI も違い(論文の 5 つのどれでもない)、人間記事の取り方も違うのに、向きは全部そろいました。
差は論文より小さく(論文 0.22〜0.65、ここ 0.07〜0.35)、これは §2 の大きさの差と同じ形です。

**Jev の読みで一番開いた値**も、論文の「整っていて自分で予告する形」と同じ側に並びます:
冒頭で読者の状況を映す(AI 0.82・人間 0.44)、時間の留保を混ぜる(人間 0.67・AI 0.31)、
未来を漠然と語る(AI 0.80・人間 0.49)、外部の権威を引かない(AI 0.71・人間 0.42)、
比較の数字そのものを出さない(AI 0.69・人間 0.40)。

<a id="title"></a>

## 4. リリースの人間記事には、タイトルが無い

核の 2 番目に大きい値は「**効用を最初に約束する場所 = タイトル**」(AI 寄り、差 0.624)です。
ところが、リリースのコードを追うと**採点者は人間記事のタイトルを一度も見ていません**:

1. 人間記事は `trafilatura.bare_extraction(...).text` —— **本文だけで、タイトルは別の欄**(`study_b/spot_check.py`・`build_corpus.py`)。
   こちらで取った 55 本も、本文がタイトルで始まるのは 3 本だけ(本文中の見出し)。
2. AI 記事は**「タイトル行から書き始めよ」**と頼まれて生成される(`study_b/generate_mirrors.py`)。
   正規化は `# ` を剥がすが**行そのものは残す**。
3. 採点は `story_human` と mirror の `text` を**そのまま**渡す(`study_b/r5_apply.py`)。人間側に何も前置きしない。

つまり**「効用はタイトルで約束されているか」を、人間記事ではタイトル抜きで、AI 記事ではタイトル込みで聞いている**。
これは正規化の設計が消そうとした種類の非対称(「パイプラインを検出してしまう」—— `normalize.py` の docstring)と同じ形です。

そこで**人間記事の先頭にマニフェストのタイトルを 1 行戻した対照腕**(`titled`)を採点しました。

| | 人間(そのまま) | 人間(タイトルを戻す) | AI |
| --- | --- | --- | --- |
| PUR_OUT_003 = タイトル | **0.200** | **0.618** | 0.545 |

**タイトルを戻すと向きが逆になります。** 人間記事の方が、AI 記事よりタイトルで効用を約束している。
ほかの 9 値はタイトルを戻しても向きが変わりません(最初の単位の前の主張が 0.436 → 0.364 と動く程度)。

分類器への効き方:

| | そのまま | タイトルを戻す |
| --- | --- | --- |
| 構造(187)macro-F1 / AUC | 0.782 / 0.878 | 0.773 / 0.877 |
| 核だけ(10)macro-F1 / AUC | 0.736 / 0.832 | **0.652** / **0.748** |
| 核の値を学習なしで足す(§7 の A0)AUC | 0.790 | **0.699** |

**全体の検出は変わらない**(187 特徴のうち 1 つなので)。**変わるのは「AI の形」の説明の方**です ——
論文が「AI の記事はタイトルで効用を約束する」と書いている部分は、**少なくとも一部がこの非対称で説明できる**。

言えないこと: ここの採点者は gemini ではなく Jev で、AI は Claude です。ただしこの機構は**テキストに無いものは誰にも読めない**という話なので、
採点者を替えて消えるとは考えにくい。直すならリリース側で**人間記事にタイトルを前置きするか、AI 記事の 1 行目を剥がすか**のどちらかで、
それで PUR_OUT_003 と核の選択がどう変わるかは、**gated な記事単位データを持っている著者にしか測れません**。

<a id="reword"></a>

## 5. 言い換え攻撃 —— 構造は動かず、style だけが落ちる

各 AI 記事を、**書いた本人**がリリースの LAMP プロンプト(7 種の「AI っぽい癖」を span ごとに直す、事実とリンクは全部残す)で言い換えました。
学習はし直さず、元の AI 記事で学習した分類器を当てるだけ(論文と同じ手順)。

- **ゲート**(リリースの `GATES.md` と同じ基準): 長さの比 平均 0.967(最小 0.906、[0.6, 1.4] の外 **0 件**)、丸写し **0 件**。
- **攻撃の強さ**: 元の 13 語連続が言い換え後に残る割合 **0.107**(論文 0.269)。**論文より強く書き換わっている。**
- **結果**: 構造 **0.782 → 0.782**、全部 0.800 → 0.818、**style だけ 0.627 → 0.581**。

論文(構造 98.0 → 98.1、style 88.1 → 87.1)と**同じ形**です —— 言い回しを読む特徴だけが言い回しの攻撃で落ちる。

<a id="rarity"></a>

## 6. 人間は稀な構造に居るか —— 向きは出る、大きさは出ない

リリースの定義どおり(構造 187 特徴を z 化、最近傍 25 本までの平均距離、プールした分布でのパーセンタイル):

| | ここ | 論文 |
| --- | --- | --- |
| 人間 / AI の平均パーセンタイル | 0.552 / 0.439 | 0.838 / 0.435 |
| Cohen's d | **0.393** | **1.83** |
| AUC | 0.612 | 0.901 |
| 人間が自分の AI 版より稀 | **0.727**(偶然 0.5) | 0.855(偶然 0.167) |

向きは同じで、人間は 4 組に 3 組で自分の AI 版より稀です。**ただし大きさは 5 分の 1。**
論文は AI 5 源が**同じ構造に群がる**ことを大きさの源にしている(図 1b)ので、
**AI 源が 1 つ・プールが 1 : 1 のここでは、その部分がそもそも測れません**。
ここから「論文の効果は小さい」とは言えず、「この標本では確かめられなかった」までです。

## 7. Jev に文脈を渡して判定機にする

ここからが 2 つ目の問いです。**この標本のラベルを 1 つも見せずに**、論文の知見だけを渡して「AI が書いたか」を聞きます。

| 腕 | 渡すもの | 形 |
| --- | --- | --- |
| **bare** | 何も渡さない | `noul`「この記事は AI の言語モデルが書いた」 |
| **shape** | 論文 §6 の「整っていて自分で予告する形」の説明(論文の言葉に近い 5 文) | 同じ `noul`、instructions の前に置く |
| **core** | 核 10 値を、**測定器の質問文と「その答えは AI 寄り / 人間寄り」**の 10 行で(リリースから生成) | 同じ `noul` |
| **A0** | **同じ核 10 値を、10 個の型付き質問として**(§2 の採点そのもの)。答えにリリースの向き(±1)を掛けて足すだけ | 学習なし |

セルは **macro-F1(0.5)/ AUC [95% CI] / 対**、右端は**閾値を他社の記事で当てはめた** macro-F1([25](25-thresholds.md) の読み方)。

| 腕 | そのまま | 言い換え後 | 人間 / AI の平均 | 閾値を当てはめた F1 |
| --- | --- | --- | --- | --- |
| bare | 0.399 / 0.657 [0.575, 0.743] / 0.782 | 0.399 / 0.618 / 0.709 | 0.671 / 0.742 | 0.656 |
| shape | 0.449 / 0.680 [0.602, 0.763] / 0.791 | 0.449 / 0.634 / 0.718 | 0.696 / 0.787 | 0.654 |
| core | 0.433 / 0.631 [0.553, 0.724] / 0.745 | 0.427 / 0.585 / 0.673 | 0.682 / 0.749 | 0.593 |
| **A0**(同じ 10 値を質問に分ける) | — / **0.790** [0.735, 0.853] / **0.927** | — / 0.789 / 0.891 | | |
| A0、確率で | — / 0.786 [0.743, 0.841] / **0.982** | | | |
| A0、**10 特徴だけを 1 要求で**(20 問) | — / 0.775 [0.716, 0.838] / 0.927 | — / 0.786 / 0.927 | | |
| 参考: 構造 187 を学習(§2) | 0.782 / 0.878 / 0.982 | 0.782 / 0.867 / 0.964 | | |

わかったこと:

- **丸ごと聞くと、Jev はほとんど全部を「AI」と言う。** 人間記事の平均も 0.67〜0.70 で、0.5 で読むと macro-F1 0.40〜0.45。
  閾値を当てはめても 0.59〜0.66 止まり。**識別の力(AUC)そのものが 0.63〜0.68 しかない。**
- **論文の知見を文章で足しても効かない。** shape は bare に +0.023(CI の中)、core は **−0.026**。
  10 個の手がかりを 1 つの instructions に詰めると、**1 つの判断に 10 個の判断を同時にさせる**ことになり、それは Jev の形ではない。
- **同じ 10 個を質問に分けると、学習なしで AUC 0.79・対 0.93。** 渡している知見は core 腕と**完全に同じ**
  (同じ特徴・同じ向き。重みは全部 1)。違うのは**判断の単位**だけです。
  確率で足すと**対が 0.982**になり、187 特徴を学習した分類器と並びます。
- **言い換えに強いのも分けた方。** A0 は 0.790 → 0.789、丸ごと聞く腕は AUC が 0.04〜0.05 落ちる。

**つまり「コンテキストを与えて判定機を作る」は、文脈を文章で渡すと成り立たず、文脈を質問に展開すると成り立ちます。**
これはこのリポジトリで前にも出た形です —— [22](22-code-criteria.md) で、曖昧な 1 問を具体的な指標に分けて名前で聞くと捕まるバグが増えた。

**値段。** 上の A0 は 307 問の要求の中から 10 特徴を読んでいるので、**10 特徴(20 問)だけの要求**でも採り直しました:
答えは 4,400 項目中 **98.0% が同じ**で、AUC **0.775**(307 問の中では 0.790、CI は重なる)。
入力は 1 記事 **約 3,100 トークン = $0.00013**。**判定機としては 20 問の要求で足ります。**

**判定機として使うなら:**

1. **質問は特徴に分ける**(核 10 値なら 10 問)。**向きは論文のものを使い、重みは付けない** —— それで AUC 0.79。
2. **閾値は必ず当てはめる。** 丸ごと聞く `noul` は人間記事でも 0.67 が平均で、0.5 は使えない。
3. **ラベルが数十組あるなら**、187 特徴を確率で符号化してロジスティックを乗せる(AUC 0.93)。
4. **タイトルの扱いを両側でそろえる**(§4)。PUR_OUT_003 は、抽出の仕方次第で向きが逆になる。

## 8. 2023 年以降の人間記事で、誤検出はどこまで増えるか

§2〜§7 の人間記事は全部 ChatGPT 以前(〜2022)です。使う場面で出会うのは**今の人間が書いた記事**で、
人間の側も 5 年分のテンプレ的な記事を読んで書いています。判定機が「AI の形」ではなく**「2022 年以前らしさ」**を見ているなら、
今の人間記事を大量に AI と誤判定するはずです。

**集め方**(`src/fetch_recent.py`)。同じ val/test の 70 社の sitemap から、**2022 年以前の記事と同じ URL の区画**
(`/blog/` など)に居て、マニフェストに無く、trafilatura の日付(htmldate)が **2023-01-01 以降**のものを、
論文と同じ門(600〜2,500 語・英語)に通して 1 社 4 本まで。**29 社・102 本**(うち 73 本は §2 の 33 社)、
年別に 2023: 27・2024: 25・2025: 13・2026: 37。台帳は [`records/recent_ledger.csv`](../experiments/slopshape/records/recent_ledger.csv)。
採点は §2 の人間記事と同じ形(本文のみ・タイトルなし)で、同じ 3 種の要求(307 問・核 20 問・判定 3 腕)。

**読み方の前提。** 2023 年以降の記事が人間の手だと**証明する方法は無い**ので、ここで測れるのは**検出率**で、
それは**誤検出率の上限**です(混じっている AI 記事の分だけ上がる)。そして 2026 の 37 本は、日付が「最終更新日」を拾っている可能性があります。

**閾値はすべて 2022 年以前のデータだけで決めました。**
`fpr10` は 2022 年以前の人間記事の 10% しか引っかからない閾値(55 本の 90 パーセンタイル)、`F1` は 2022 年以前の対で macro-F1 が最良になる閾値です。
学習する腕(構造 187)は、2023+ の記事をその会社を抜いて学習したモデルで採点しています。

| 判定機 | AUC: AI 対 旧人間 | AUC: **2023+ 対 旧人間** | `fpr10`: 旧人間 / AI の検出 / **2023+** [95% CI] | 年別(2023 / 24 / 25 / 26) | `F1` の閾値: 旧人間 / AI / **2023+** |
| --- | --- | --- | --- | --- | --- |
| A0、核 10 だけ(20 問) | 0.775 | **0.560** | 0.091 / 0.400 / **0.088** [0.037, 0.145] | 0.07 / 0.08 / 0.08 / 0.11 | 0.400 / 0.855 / 0.520 |
| A0、核 10、確率で | 0.786 | 0.554 | 0.091 / 0.418 / **0.098** [0.030, 0.176] | 0.07 / 0.08 / 0.08 / 0.14 | 0.400 / 0.836 / 0.529 |
| **構造 187、確率で、学習** | **0.929** | **0.532** | 0.091 / **0.873** / **0.157** [0.068, 0.266] | 0.11 / 0.16 / 0.15 / 0.19 | (同じ閾値になった) |
| 判定: bare | 0.657 | **0.608** | 0.091 / 0.145 / **0.294** [0.159, 0.460] | 0.26 / 0.40 / 0.54 / 0.16 | 0.545 / 0.891 / 0.676 |
| 判定: shape | 0.680 | **0.656** | 0.091 / 0.182 / **0.294** [0.168, 0.444] | 0.30 / 0.52 / 0.38 / 0.11 | 0.364 / 0.691 / 0.588 |
| 判定: core | 0.631 | **0.656** | 0.091 / 0.055 / **0.265** [0.135, 0.422] | 0.19 / 0.40 / 0.62 / 0.11 | 0.455 / 0.745 / 0.686 |

わかったこと:

- **構造で判定する腕では、2023+ の記事は 2022 年以前の人間記事とほとんど区別されない**(AUC 0.53〜0.56。0.5 が「同じに見える」)。
  **構造 187 の学習版**は、2022 年以前の人間記事の 9% しか引っかけない閾値で **AI の 87% を拾い、2023+ の記事は 16%**(CI 7〜27%)を引っかける。
  これが上限なので、**実際の誤検出は 16% 以下**。旧人間の 9% からの上昇分には、2023 年以降に混じった AI 記事の分が入っています。
- **核 10 値の足し算(A0)は、2023+ でも誤検出がまったく増えない**(8.8〜10.8%、旧人間 9.1%)。ただしその閾値で**拾える AI は 4 割**。
  **慎重な閾値で使う限り安全だが、弱い。**
- **丸ごと聞く判定は、AI より「新しさ」をよく見分ける。** 2023+ 対 旧人間の AUC(0.61〜0.66)が、**AI 対 旧人間の AUC(0.63〜0.68)とほぼ同じか上**で、
  `fpr10` の閾値で 2023+ の **27〜29%** を引っかけながら AI は 6〜18% しか拾わない。**この腕は判定機として使ってはいけない**ことが、§7 より強く言えます。
- **年とともに少しずつ上がる**(構造 187 で 2023: 11% → 2026: 19%)。誤検出が増えているのか、AI 記事が混じる割合が増えているのかは、**このデータでは分けられません**。

**実用の目安**(§7 の続き): 構造 187 を学習させた判定機を 2022 年以前の人間記事で誤検出 9% の閾値に置くと、
**今の人間記事での誤検出は多くて 16% 程度、AI の検出は 87%**(Claude の無編集の一発生成について)。
並べ替えや人が見る前の絞り込みには使える水準で、**1 本ずつの断定には足りません**。旧人間 55 本で決めた閾値そのものも粗い(90 パーセンタイルは上位 5〜6 本で決まる)ので、
使う側の記事で閾値を当てはめ直すのが前提です。

## 9. 使うための 1 本: `src/suspect.ts`

§2〜§8 の結論を、記事ファイルを渡すと疑わしさを返すスクリプトにしました。**判定ではなく、並べ替えと人が見る前の絞り込みのための信号**です。

```bash
cd experiments/slopshape
npx tsx src/suspect.ts --fit                         # 記録から当てはめ直す(API 不要)。records/suspect-model.json はコミット済み
TYPESAFEAI_API_KEY=... npx tsx src/suspect.ts post.md # 187 特徴・1 記事 約 $0.001
TYPESAFEAI_API_KEY=... npx tsx src/suspect.ts --core post.md  # 核 9 値・1 記事 約 $0.0001
```

```json
{"file":"post.md","mode":"full","score":0.88,"percentile":0.95,"flag":true,
 "why":["Success Criterion Visibility: measurable threshold or metric","Reader Situation Mirroring: present", ...]}
```

- **入力は 1 行目にタイトルを置いたテキストか markdown。** §4 の非対称を持ち込まないよう、モデルは**タイトルを戻した人間記事**と AI 記事で当てはめてあります
  (会社ごとに抜いた out-of-fold で AUC **0.915**。§2 のタイトル抜きの 0.929 とほぼ同じ)。
- `score` は構造 187 特徴を確率で符号化したロジスティックの P(AI)、`percentile` は 2022 年以前の人間記事の中での位置、
  `flag` は**2022 年以前の人間記事の 9% しか引っかけない閾値**を超えたか(その閾値で AI の **85.5%**。§8 の 2023+ で上限 16%)。
- `why` は**その記事に実際にある値**のうち、スコアを最も押し上げたもの 5 つ。lint として読むならここです。
- `--core` は核 10 値のうち **9 値**の足し算です。「タイトルで効用を約束」は、タイトルがある入力では向きが逆になるので外しました
  (外すとタイトル込みの AUC が 0.691 → 0.737)。安いぶん弱く、同じ閾値で拾える AI は 4 割程度。

**閾値は 55 本の人間記事の 90 パーセンタイルで、粗い**です。使う側の記事(できれば人の手だと分かっているもの)を数十本通して、`flag` の閾値を置き直してから使ってください。
