# 02. ヘッドレス 3v3 MOBA(視界と戦場の霧)

LoL を圧縮した対戦ゲームで Jev にチームを操作させる。2 レーン + ジャングル、
3v3、視界と戦場の霧あり、**判断は視界に入っている情報だけ**で行う。

再現:

```bash
moon run --target native cmd/moba -- --a jev --b scripted --games 3
moon run --target native cmd/moba -- --a scripted --b scripted   # sim の健全性確認(API 不要)
moon run --target native cmd/moba -- --a jev --b scripted --games 1 --max-ticks 12 --verbose
```

---

## 1. なぜこの題材が Jev に合うか: チーム視界 = 1 state, 3 質問

LoL では**視界がチームで共有される**。つまり 1 tick あたり、チームごとに
**観測は 1 つしかないのに、判断が必要なキャラは 3 体**いる。
これは [speculative fan-out](00-api-notes.md#speculative-fan-out) がそのまま当てはまる形で、
何も無理をしていない:

- state(盤面・視界・記憶)を **1 回だけ**送る
- `choice` を**キャラごとに 1 問**、criteria はそのキャラの合法手だけ
- ついでにチーム単位の判断も同じリクエストに乗せる(state はもう払っている)

実測で **1 リクエストが 2.6〜2.8 体分の行動を決めている**:

| | リクエスト | 決定したキャラ行動 | ms/リクエスト | **ms/キャラ判断** |
| --- | --- | --- | --- | --- |
| A=jev, 3 戦 | 79 | 218 | 210 | **76** |
| B=jev, 3 戦 | 108 | 271 | 184 | **73** |

**1 キャラあたり 73〜76 ms。** 目標だった click per sec 2(= 500 ms/判断)に対して
6 倍以上の余裕があり、3 体を 1 リクエストにまとめたことがそのまま効いている。
キャラごとに別リクエストを投げていたら、state を 3 回送って 3 倍のトークンを払うことになる。

## 2. 結果

相手は組み込みのスクリプト bot(低 HP で撤退、数の有利で殴る、それ以外はレーンを押して farm)。

| | 結果 | 決着 tick |
| --- | --- | --- |
| A=jev vs B=scripted | **3 — 0** | 29, 29, 30 |
| A=scripted vs B=jev(先後入れ替え) | **0 — 3** | 37, 37, 38 |

**両サイドから 6 戦全勝。** マップは対称なので、サイド有利ではない。
コストは 1 戦あたり入力 5 万トークン前後、**$0.002/戦**。

**不正な手は 489 判断すべてで 0 件。** criteria をその場の合法手そのものにしているので、
**不正手が表現できない**(選択肢の集合が合法手の集合)。
五目並べ CLI が API 失敗時だけフォールバックしていたのと同じ設計で、
ここでは「盤外の手を打つ」という失敗モードが構造的に消える。

## 3. 何をしていたか

`--verbose` の冒頭(A が Jev):

```
tick 1  A_top: move_m_top (0.84)   A_jungle: move_m_jg (0.83)   A_bot: move_m_bot (0.75)
        [team read] danger=0.08/3@0.92   unseen enemies probably at b_jg@0.33
tick 2  A_top: attack_champ_3 (0.27) A_jungle: attack_champ_4 (0.29) A_bot: move_b_bot (0.17)
        [team read] danger=0.87/3@0.66  unseen enemies probably at b_base@0.58
tick 3  A_top: move_b_top (0.41)   A_jungle: attack_champ_4 (0.30) A_bot: attack_structure (0.68)
        [team read] danger=1.07/3@0.59
tick 4  A_top: attack_structure (0.79) A_jungle: attack_champ_4 (0.38) A_bot: attack_structure (0.74)
        [team read] danger=1.41/3@0.34
```

3 体が同時に前進して接触し、そこから **top と bot が建物を割り、jungle が敵ジャングラーを
足止めし続ける**。MOBA でいうスプリットプッシュと体を張った足止めで、
こちらが手続きで書いたものではなく、合法手の選択の積み重ねから出ている。

`danger` は状況を追えている(0.08 → 0.87 → 1.41)。

### confidence が判断の質を区別している

面白いのは confidence の分布で、**行動の種類によってきれいに分かれる**:

| 行動 | confidence |
| --- | --- |
| 建物を攻撃 | 0.68 〜 0.84 |
| 敵チャンピオンを攻撃 | 0.27 〜 0.52 |
| 見えない敵の位置を推測 | 0.31 〜 0.58 |

建物を割るのは明確な前進なので自信が高く、**殴り合いは本当に紙一重**なので低い。
これは誤りではなく正しい報告で、
[01 の教訓](01-shell-risk.md#3-順序のある結論は-score-で聞く)どおり
confidence を素直に使える形になっている
(例えば「戦闘判断が conf < 0.35 のときは撤退側に倒す」という方針をコード側で書ける)。

見えない敵の位置推測は 11 択で 0.31〜0.58。**情報がないときに自信を持たない**のは
望ましい挙動で、ここで 0.9 が返ってきたら逆に信用できない。

## 4. 正直な限界

- **スクリプト bot は強くない。** 同じ bot 同士だと完全対称で毎回引き分け、建物に一切
  ダメージが入らない(決定的方針 × 対称マップなので当然)。つまり 6-0 は
  「受け身のレーン bot より強い」であって「MOBA が上手い」ではない。
  次はもっと強いスクリプト(集団で 1 レーンに寄る、敵が見えないときは引く)を相手にすべき。
- **戦場の霧を活かしているかは未検証。** `enemies_last_known`(最後に見た場所と何 tick 前か)を
  state に入れてはいるが、それが判断を変えているかは測っていない。
  同じ局面を「記憶あり / なし」で比較すれば効果が出るはず。
- **1 tick = 1 手の同時解決**なので、実際の MOBA の連続時間・射程・スキルは無い。
  CPS 2 相当の離散化という割り切り。
- 決着が 29〜38 tick に集中しており、局面のバリエーションが乏しい。

## 5. この実験で確定したパターン

1. **共有状態 + 複数エージェントは fan-out の理想形。** 観測が 1 つで判断が N 個なら、
   N 個の質問を 1 リクエストに入れる。ここでは 1 キャラ 73 ms まで落ちた(1 節)。
2. **criteria をその場の合法手にすると、不正手が表現できなくなる。**
   489 判断で 0 件。文字列で手を生成させる方式と決定的に違う点(2 節)。
3. **confidence は判断の種類ごとに意味のある差が出る。** 明確な前進は高く、
   紙一重の交戦は低い。コード側の方針(迷ったら引く)に素直に繋げられる(3 節)。
4. **コードが既に知っていることは criteria の説明文に書く。**
   「そのノードは何 hop 先か」「タワーがあるか」「見えているか」を添えてある。
   五目並べの `WINS` / `BLOCK` ヒントと同じ発想。

## 6. 次に試すこと

- 強いスクリプト bot(集団プッシュ + 引き)との対戦。今の 6-0 は相手が弱い。
- `enemies_last_known` を state から抜いた ablation。記憶が効いているかの確認。
> **→ [10](10-jev-vs-jev.md) で測った。** 独立プロセスの Jev 同士は 6/6 決着(scripted は 3/3 引き分け)、
>   3 体は明示的な調停なしにレーンが割れた。以下は当初のメモ。

- Jev vs Jev で、同じ state に対する 3 体の答えが**互いに矛盾しないか**
  (3 体とも「自分が足止めする」と答えたら破綻する)。役割分担を 1 問の
  `choice`(誰が足止めするか)で先に決めてから各自の行動を聞く二段構えと比較したい。
