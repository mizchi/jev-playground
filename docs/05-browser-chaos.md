# 05. ブラウザ探索の次操作選択(chaosbringer)

[chaosbringer](https://github.com/mizchi/chaosbringer) は次の操作を重み付きランダムで選ぶ。
これを Jev に置き換えると何が変わるか。

再現:

```bash
cd experiments/browser-chaos
npm install
TYPESAFEAI_API_KEY=... npx tsx src/run-spa.ts --steps 20 --seeds 3 [--verbose]
```

---

## 1. 結果

対象は `app/index.html` の「ゲート付きショップ」。`#/confirm`(注文完了)に到達するには
**8 手連続で正しい選択**が要り、各画面には 14〜17 個のコントロールがあり、
進捗を巻き戻す罠(「カートを空にする」「アカウント削除」)が 2 つ置いてある。

| | 到達状態数 | フロー深度 | 注文完了 | 無駄手 |
| --- | --- | --- | --- | --- |
| weighted-random | **8.3/14** (8, 9, 8) | 1, 1, 1 / 5 | **0/3** | 4, 6, 9 |
| Jev | 7.0/14 (7, 7, 7) | **5, 5, 5 / 5** | **3/3** | 1, 2, 2 |

コスト: 60 リクエスト、入力 74,920 トークン、**183 ms/手、3 ラン合計 $0.0032**。

Jev の 1 ラン(20 手中の最初の 11 手で注文完了):

```
 0. link "Products"            5. email field "Email address"   10. button "Place order"  <- 完了
 1. button "Add Widget to cart" 6. button "Continue to delivery"
 2. link "Cart"                7. button "Continue to payment"
 3. button "Proceed to checkout" 8. text field "Delivery address"
 4. button "Continue to delivery" 9. button "Continue to payment"
```

**ランダムは幅、Jev は深さ。** ランダムのほうが到達状態数は多い(8.3 > 7.0)。
行き止まりのナビリンクを踏み回るからで、Jev は目的に寄与しないので踏まない。
つまり**置き換えではなく併用が正しい**: chaosbringer の `compositeDriver` /
`samplingDriver` はまさにこのための組み合わせ子で、幅はランダム、深さは Jev に任せられる。

## 2. 効いたのは質問ではなく state だった

ここが一番の学びで、4 回作り直してようやく通った。**質問(choice + noul 2 問)は
初回から最後まで一字も変えていない。** 変えたのは state に何を入れるかだけ。

| # | state に入れたもの | 結果 |
| --- | --- | --- |
| 1 | goal、URL、候補一覧、既訪状態 | **`Continue to payment` を 7 回連打**して停止。深度 3 |
| 2 | ＋「直前の操作は画面を変えなかった」 | ループは移動したが解消せず、無駄手 9。深度 3 |
| 3 | ＋ 無効だった候補を criteria から除外 | 連打は止んだが**さまよう**。深度 2 に悪化 |
| 4 | ＋ **画面の表示テキストとフォームの現在値** | **深度 5、注文完了 3/3、無駄手 1〜2** |

### 変化 1 → 2: 「無駄だった」を伝えても連打は止まらない

ゲートされた `Continue` ボタンは、何度見ても「次に進む正しいボタン」に見える。
`last_action_changed_the_page: false` を state に入れると連打の対象は移ったが、
今度は同じ入力欄を 6 回埋め続けた。そのときの confidence は **0.40〜0.47** で、
**モデルは迷っていることを正しく報告していた**。信号はあったのに、使っていなかったのは私のコード。

### 変化 2 → 3: 選択肢から消すほうが、言葉で言うより効く

「これは無効だった」と state で伝えるのをやめ、**その候補を criteria から取り除いた**
(画面の指紋が変わったら忘れる)。連打は完全に止まった。

> **原則: 繰り返してほしくない選択は、モデルに我慢させるのではなくコード側で消す。**
> モデルに「同じことをするな」と覚えさせるより、選択肢を渡さないほうが安く確実。

ただしこれだけでは深度が 2 に下がった。理由が次。

### 変化 3 → 4: 判断に必要な情報を渡していなかった

候補の説明(`button "Continue to delivery"`)だけでは、
**メールアドレス欄がもう埋まっているのかどうか分からない**。
だから「Continue を押していいか」を判断できず、無関係なボタンに逃げていた。

画面の表示テキストと**各フォーム欄の現在値**を state に入れた瞬間に通った。
[01 の文脈実験](01-shell-risk.md#2-同じコマンドでも文脈で判断が変わる)と同じ結論で、
**Jev を賢くするのではなく、こちらが持っている情報を渡し忘れないこと**が仕事の中身だった。

## 3. 途中で踏んだ自分のバグ(教訓込み)

変化 3 で深度が下がった真因は、Jev ではなく**私の「何か起きたか」判定**だった。
画面の指紋を `location.hash + 表示テキスト` で取っていたので、
**入力欄に文字を打つと指紋が変わらない**。結果、完全に有効な「メール欄を埋める」操作が
「無効」と記録され、除外リストに入り、正解の経路が 2 手とも封じられていた。

指紋にフォームの値を含めたら直った。

> 「その操作は効果があったか」は自明ではない。DOM のテキスト差分だけでは
> フォーム入力・スクロール位置・`aria-expanded` などが取れない。
> **除外ロジックを入れるなら、効果判定の取りこぼしが即「正解を封じる」形で効く**ので、
> 指紋の設計は除外ロジックより先に固めるべきだった。

## 4. chaosbringer 側への指摘: driver の候補一覧が 1 ページ 1 回しか作られない

`src/jev-driver.ts` は chaosbringer の `Driver` インターフェース実装そのままで、
`chaos({ driver })` に差せて実際に動く(実測でリクエストが飛ぶ)。
ただし **SPA では期待どおりに働かない**。

`crawler.js` の driver ループはこうなっている:

```js
async performDriverActions(page, url, targets) {
  const candidates = targets.map((t, i) => ({ ... }));   // ループの外
  for (...) { const pick = await driver.selectAction({ candidates, ... }); }
}
```

`targets` はページ訪問時に 1 回だけ収集され、`candidates` もループの外で作られる。
ハッシュ遷移やモーダルのように**ナビゲーションなしで DOM が変わるアプリでは、
2 手目以降は古い候補一覧から選んでいる**ことになる。

実測では `#/products` に居るのに候補が常にトップページのナビ 15 件で、
`Add Widget to cart` が一度も候補に出てこなかった:

```
/#/products step=1 cands=15 -> link "Cart"       # Add to cart は候補に無い
```

これは `weightedRandomDriver` と `aiDriver` にも等しく当たる話で、Jev 固有ではない。
per-step driver を活かすなら、**候補収集をステップごとに(あるいは DOM 変化時に)やり直す**
必要がある。この実験は比較の公平性のためだけに `src/spa-bench.ts` で
自前のステップループを書いており、候補抽出と操作実行は両アームで共有している
(差分は「どのインデックスを選ぶか」だけ)。

`launchOptions` が npm 公開版 `0.9.0` に無く git HEAD にはある点も踏んだ
(`experiments/browser-chaos` は Playwright を 1.56.0 に固定して回避)。

## 5. この実験で確定したパターン

1. **state に判断材料を全部入れる。** 質問を捏ねるより効果が大きかった(2 節)。
   候補の名前だけでは足りず、画面の内容とフォームの現在値が要る。
2. **繰り返させたくない選択はコード側で criteria から消す**(2 節)。
   言葉で禁止するより安く確実。
3. **幅はランダム、深さは Jev。** 併用が正しく、置き換えは損(1 節)。
4. 除外ロジックを入れるなら**効果判定を先に固める**(3 節)。取りこぼしが正解を封じる。
