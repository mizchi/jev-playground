## 結論(先に)

**1. a の答えは「どちらでもない」。効果は全部が交互作用でした。**
宿題は「記憶か意図か」の二択を出していました。
**訪問回数だけ −6、ゴール文だけ −12、両方で +60**
(地図化セル数、`jev` 比。exact p = 0.042)。
**片方ずつではどちらも基準より悪く**、両方でだけ効きます ——
訪問回数は「歩いていない方を選べ」と言われるまで不活性で、
その指示は数えた回数が無ければ実行不能。**二択の両方が外れでした。**

**2. そして b が見つけた矛盾を取り除くと、さらに上がったので出荷しました**(§a.3b)。
壁に訪問回数を付けるのをやめるだけで
**地図化 124 → 151、縦の却下 73% → 23%、歩いたマス 47 → 76、
ターン 64 → 142**。矛盾は**却下を買って何も売っていなかった**。
しかもそれは却下率の問題ではなく**固着**の原因でした ——
出荷前は 1 マスに **200 回**(= 1 ゲーム丸ごと)却下され続けていて、
出荷版の最悪は 12 回です。

**3. k —— 記憶は単独で効きます。壁を推薦するのをやめさせた後は。**
`jevcount`(矛盾入りの回数)は単独で **−6**、
ガードを入れた `jevcountguard` は単独で **+12**(p = 0.069)、
却下も 20% → 6%。差は**ガードだけ**。
だから上の「全部が交互作用」は**矛盾を含んだ記憶**を測った結論でした。
正しくは**効くのは記憶の側、文の側は単独では効かない** ——
[34 §2.4](34-roguelike.md) は**どちらの半分かについては正しく**、
報告した数字を自分のペイロードの矛盾が抑えていただけでした。

**4. l —— 落とせないエントリに質問を使っていました。節約は小さい。**
`jev-compact` の候補は `!pinned()` で絞っていましたが、
**相方が pin されたエントリは何点でも動けません**。
`reachable()` を足しました。**最初の実装は 1 パスで間違っていて、
自分のテストが捕まえました**(`closePairs` は同じ理由で不動点まで回していて、
そのコメントに書いてあった)。
節約は **1 transcript あたり 0〜2 問、出荷値では 0 問** ——
買えるのは理由文の正確さで、節約額ではありません。

**5. b の前提が間違っていました。**
宿題は「却下された手の**画面上の位置**は記録に入っているので、
リクエスト 0 件で分かる」と書いていました。**入っていません。**
`play.ts` は毎ステップ `probe.hero.x/y` を計算していて
(`jevmemo` に渡す訪問回数のために必要)、
**`StepRow` に入れる前に捨てています**。

**6. それでも b は答えが出ました。しかも聞かれたより良い答えが。**
`jevmemo` の却下 19% は**地図の縁でも列の読み違いでもなく、
自分のプロンプトの矛盾**でした ——
**壁は必ず「まだ立ったことがない」**ので、
memory が付ける文は壁に対して
「you have never stood there」と読み、
`MEMO_GOAL` は「歩いていない方を選べ」と言う。
**memory が壁を推薦している。**
そして位置を記録し直した a の run で、b の元の問いにも答えが出ました ——
**却下は地図の縁ではありません。逆方向です**
(却下は境界から 6.4、通った手は 4.7)。

**7. c の答えは「ランキングが最初から立っていなかった」。**
5 段階と 9 段階を**同じリクエストで**聞いて、順位は動きました
(上位 2 件が入れ替わり、spearman 0.900)。
しかし**隣接ペア 4 組のうち、両方の尺度で分離しているのは 0 組**。

解像度の問題ではなく、**ゲーム 6 本ずつでは並べられない**。

**8. f は「形は答えを動かすが、決定は動かさない」。**

## a. `jevmemo` の 2 つの追加、どちらが効いたのか

[34 §2.4](34-roguelike.md) は**訪問回数**と**ゴール文 1 文**を同じアームで足して
地図化 48 → 152 を報告しました。その数字は**どちらが効いたか言えません**。
宿題の文はこう書いています ——
**「1 文だけで上がるなら、足したのは記憶ではなく意図だった」**。

5 アーム、6 ゲームずつ、6,000 リクエスト・$0.3028:

```
  arm          counts  sentence   mapped   walked   refused   illegal   turns
  jev              no        no       64       16        3%         0     195
  jevcount        yes        no       58       19       20%         0     161
  jevintent        no       yes       52       15        8%         0     185
  jevmemoraw      yes       yes      124       47       69%         0      64
  jevmemo         yes       yes      151       76       30%         0     142
```

### a.1 答えは「どちらでもない」—— 効果は全部が交互作用

```
  arm          mapped   range      vs jev

  jevintent        52   30..86        -12    the sentence alone
  jevmemoraw      124   50..258        +60   both, 矛盾あり(34 が測ったもの)
  jevmemo         151   24..232        +86   both, 矛盾を除いた —— 出荷
```

**片方だけでは何もしません。どちらも基準よりわずかに悪い。**
両方でだけ大きく良くなります。

> **この読みは宿題 k で半分覆りました → [§k](#k-jevcount-にもガードを入れる--記憶は単独で効く矛盾が無ければ)。**
> 上の `jevcount` は**矛盾入りの記憶**です。ガードを入れた `jevcountguard` は
> **単独で +12**(AUC 0.764、exact p = 0.069)。
> **記憶は単独で効きます —— 壁を推薦するのをやめさせた後は。**
> 「全部が交互作用」は、**矛盾を含んだ記憶**を測った結論でした。

ダンジョンは制御できず(§a.4)6 本ずつなのでレンジは全ペアで重なります。
なので**平均ではなく順位**で、しかも 6 対 6 なら
帰無分布は C(12,6) = **924 通りだけ**なので **p 値は数えられます**:

```

  jevcount                      17/36 (AUC 0.472)               2/6    0.5736
  jevintent                     13/36 (AUC 0.361)               1/6    0.7922
  jevmemoraw                    29/36 (AUC 0.806)               4/6    0.0422
  jevmemo                       30/36 (AUC 0.833)               5/6    0.0292
```

**片方ずつは AUC 0.47 / 0.36(= 何もない、むしろ少し悪い)。
両方は 0.806 / 0.833 で p = 0.042 / 0.029。**

読み方はこうです ——
**訪問回数は「歩いていない方を選べ」と言われるまで不活性で、
その指示は数えた回数が無ければ実行不能。**

宿題は「記憶か意図か」の二択を出していました。
**第 3 の答えがあって、二択の両方が外れでした。**

**全軸で改善します。** 矛盾は**却下を買っていて、何も売っていなかった**。

### a.3 そして矛盾はエージェントを固まらせていた

`StepRow` に位置を足したので(§b.1)、宿題 b の元の問いが答えられます:

却下は境界から 6.4、通った手は 4.7。
**縁から遠いほど却下されやすい**、つまり部屋とその内壁があるところ。
宿題 b の二択(縁か列の読み違いか)のうち、**縁は反証されました**。

そして表の右半分が別のことを言っています ——
**`jevcount` と `jevmemoraw` は 1 マスに 200 回却下されています。
`maxActions` が 200 なので、1 ゲーム丸ごと同じ場所で却下され続けた。**
`jevmemoraw` のターン数 64(対 `jev` の 195)はこれでした。

固まらないアーム: `jev` 19 回、`jevintent` 74 回、**`jevmemo`(出荷後)12 回**。

> **(b) の矛盾は却下率の問題ではなく、固着の原因でした。**
> 壁に「まだ立ったことがない」と書くのをやめると、固着も消えます。

### a.3b 出荷した —— そして記録のラベルも付け替えた

依頼は「`jevmemofix` を `jevmemo` の代わりに出荷して」。やりました:

| いま | 中身 |
| --- | --- |
| **`jevmemo`** | **訪問回数 + ゴール文。ただし `steppable` が false のマスには回数を出さない**(旧 `jevmemofix`) |
| `jevmemoraw` | 出荷前の `jevmemo`。回数を全マスに出す |

**記録のラベルも付け替えました。**
`records/play.json` と `records/memo.json` の
旧 `jevmemo` 行は `jevmemoraw` に、旧 `jevmemofix` 行は `jevmemo` になりました
(データは 1 バイトも変えていません。`policy` 文字列だけ)。

理由はこの実験自身の教訓です ——
**コードで 1 つを意味し、記録で別のものを意味するラベルが、
このバグを全掃引で生き延びさせた形そのもの**でした。
`jevmemoraw` を残したのは、
[34 §2.4](34-roguelike.md) の数字がそのアームで測られていて、
**アームが存在しない主張は検査できない**からです。

そして `test.ts` が**ペイロードで**固定します ——
壁の選択肢に `stood there` が入らないこと、
壁だと**言うのはやめていない**こと、
歩けるマスでは回数が**残っている**こと
(そうでなければガードが矛盾ではなく記憶を消したことになる)、
`jevmemoraw` が矛盾を再現すること、
そして 2 つのアームの**差がガードだけ**であること。

> 結果で確認すると 6 ゲーム × 5 アームと $0.30 かかりました。
> **ペイロードで確認するとリクエスト 0 件です。**
> [38](38-agent.md) の「拡張のログではなく配線で確認する」の裏返しで、
> **配線の前にペイロードで分かるものは、ペイロードで確認する。**

**変えなかったもの、そして測れているもの:** `jevcount`
(回数だけ、ゴール文なし)は**ガードしていません**。
同じ固着を示します(1 マス 200 回、却下 20% 対 `jev` の 3%)ので、
**回数は「そこを選べ」と言う文が無くても誤らせます**。
ガードすると [§a.1](#a1-答えはどちらでもない-効果は全部が交互作用) の
「memory alone」行が別のものの測定になるので、そのままにして
[06](06-ideas.md) の宿題にしました。

### a.4 準備中に見つけたこと —— seed はダンジョンを選んでいない

この実験は最初「全アームに**同じ seed** を渡す」と書いて始めました。
`playGame` の `seed` がダンジョンを決めると思っていたからです。**決めません。**
`seed` は記録され、`rngFrom` に渡されて
**`random` policy の選択**にだけ効きます。NetHack は自分で seed します。

つまり**この実験の全ゲーム、そして [34](34-roguelike.md) の全ゲームが
独立なランダムダンジョン**です。10 手だけの試し撃ち 2 本が、
どの policy も効く前に 25 と 43 セルを地図化しました。

残る手は**ゲーム数**だけです。[34](34-roguelike.md) は 3 本で、
だから 48 対 152 にレンジがありません。
ここでは `jev` の 6 本が **48..78(平均 64)**——
**[34](34-roguelike.md) の 48 はこの幅からの 1 ドロー**でした。
宿題 c が [35 §1](35-tension.md) について見つけたのと同じ形です。

## k. `jevcount` にもガードを入れる —— 記憶は単独で効く、矛盾が無ければ

[§a.3b](#a3b-出荷した--そして記録のラベルも付け替えた) でガードを入れたのは
`jevmemo` だけでした。`jevcount`(回数だけ、ゴール文なし)も
**同じ固着を示していた**(1 マス 200 回、却下 20% 対 `jev` の 3%)ので、
**回数は「そこを選べ」と言う文が無くても誤らせる**はずです。
ガード付きの双子 `jevcountguard` を 6 ゲーム走らせました(1,200 リクエスト・$0.06)。

```
  arm          counts  sentence   mapped   walked   refused   illegal   turns
  jev              no        no       64       16        3%         0     195
  jevcount        yes        no       58       19       20%         0     161
  jevcountguard   yes        no       76       38        6%         0     189
  jevintent        no       yes       52       15        8%         0     185
  jevmemoraw      yes       yes      124       47       69%         0      64
  jevmemo         yes       yes      151       76       30%         0     142
```

```
  arm             mapped   range     vs jev   AUC     exact p
  jevcount            58   28..82       -6    0.472   0.5736
  jevcountguard       76   60..97      +12    0.764   0.0693
  jevintent           52   30..86      -12    0.361   0.7922
  jevmemoraw         124   50..258     +60    0.806   0.0422
  jevmemo            151   24..232     +86    0.833   0.0292
```

**記憶は単独で効きます。** ただし **−6 ではなく +12** で、
差は**ガードだけ**です。却下も 20% → **6%** に落ちます。

だから [§a.1](#a1-答えはどちらでもない-効果は全部が交互作用) の
「全部が交互作用」は**半分間違い**でした ——
あれは**矛盾を含んだ記憶**を測っていました。
それは記憶ではなく、**壁について「まだ立ったことがない」と言うプロンプト**です。

正しい読み:

| 足したもの | 単独の効果 |
| --- | --- |
| 訪問回数(矛盾入り) | **−6**(何もない) |
| **訪問回数(ガード付き)** | **+12**(p = 0.069) |
| ゴール文 1 文 | **−12**(何もない) |
| 両方(矛盾入り) | +60 |
| **両方(ガード付き、出荷)** | **+86** |

**宿題の二択は依然として両方外れ**ですが、理由が鋭くなりました ——
「全部が交互作用」ではなく、
**効くのは記憶の側で、文の側は単独では効かず、
両方は記憶単独よりずっと効く**。

[34 §2.4](34-roguelike.md) は**どちらの半分かについては正しかった**ことになります。
報告した数字を、**自分のペイロードの矛盾が抑えていた**だけでした。

`jevcountguard` の「jev の最良を超えた」は 1/6 なのに AUC は 0.764 ——
レンジ 60..97 が `jev` の中央より上に**一貫して**乗っていて、
時々大きく勝つのではなく**いつも少し勝つ**形です。

**`jevcount` はガードなしのまま**にしました。
[§a.1](#a1-答えはどちらでもない-効果は全部が交互作用) の
「memory alone」行がそれで測られていて、
その場で変えると**行の意味が変わる**からです。

## l. 落とせないエントリに質問を使うのをやめた

`jev-compact` の候補選びは `!pinned(e.id)` でした。
それは「このエントリは保護されているか」で、
**「このエントリは落とせるか」ではありません** ——
call と result は一緒にしか消せないので、
**相方が pin されたエントリは何点であろうと動けません**。

[38 §7.4](38-agent.md) の記録がその結果を自分の言葉で書いています:

```
4 of 22 candidates cleared 1.5 but none could be dropped:
the floors or tool-call pairing retracted every one
```

`reachable(entries, floors)` を足して候補をそれで絞りました。
`cannot-fit` の理由も
「pin されている」と「pin された相方に握られている」を区別できます。

### l.1 最初の実装は間違っていて、自分のテストが捕まえた

直接の相方が `pinned` かだけを見ていました。**1 歩足りません** ——
2 call のアシスタントターンで **2 つめの result だけ**が pin されている場合、
そのターンは到達不能で、**1 つめの result も到達不能**です
(その相方=ターンは `pinned` ではなく**到達不能なだけ**)。
1 パスでは「到達可能」と答えます。

`closePairs` は**同じ理由で不動点まで回していて**、
**自分のコメントにそう書いてありました** ——
「retracting one entry can un-drop its partner, which can un-drop a further one
when an assistant turn made two calls」。読んでいませんでした。

テストが捕まえたのは、**実装ではなく 2 call ターンを中心に書いたから**です。

### l.2 節約は小さい。そう書く

```
  keepRecent   old candidates   reachable   wasted
           1              446         438        8
           2              438         438        0
           5              414         406        8
           6              406         406        0     <- 出荷している値
```

[39](39-compact-ranking.md) の 8 transcript で、**1 transcript あたり 0〜2 問**。
`keepRecent` が pair 境界に落ちると **0**、跨ぐと 1、
3 call/ターンだと 2。**出荷している `keepRecent: 6` では 0 問**です。

**買えるのは節約額ではありません** ——
理由文の正確さと、「取り消されるだけの有料答えを使わない」ことです。
[40 §b](40-homework.md) の roguelike のバグと**同じクラス**
(構造的に選べない選択肢に注釈を付ける)ですが、
**害は軽い**: 悪い行動を推薦するのではなく、質問を捨てるだけ。
ただし `maxCandidates: 200` はコスト上限なので、
無駄な質問が本当の候補を押し出します。

## b. `jevmemo` は何を却下していたのか

### b.1 まず前提の訂正

```
  steps in the record: 2916
  steps carrying a screen position: 0
```

宿題が「リクエスト 0 件で分かる」と書いた根拠は**私の記録についての記憶違い**でした。
位置は**計算されていて、記録されていない**。
`StepRow` に `x`/`y` を足したので**次の run からは無料で分かります**が、
既存の記録では分かりません。

### b.2 答えられる半分 —— そして方向は記録に入っている

「地図の縁」と「列の読み違い」は**方向について別の予測をします**:

- **壁はどの向きでも壁。** 縁なら南北と東西に等しく出るはず。
- **列の読み違いは方向特異的。** [34 §1.1](34-roguelike.md) が測った失敗は
  **縦方向**(`@` の**行**を読み違える)。行が分からないなら北と南を間違え、
  西と東については何も間違えない。

そして決定的な事実 —— **`actions.ts` は 8 方向を必ず全部出します**、
壁に向かう手も含めて。各選択肢の本文が
「the square there shows `-` = wall」と**書いてあります**。
だから `random`(一様に選ぶ)は**ダンジョン自身の幾何**を測っていて、
他のアームはそれに対して採点できます:

```
  policy      walls avoided: vertical   horizontal   what the arm was given
  greedy                       100%          60%   a hand-written heuristic
  jev                          100%          98%   each square's glyph, in the option text
  jevbare                       13%          92%   the direction name ONLY; map from the screen
  jevmemo                       -4%          73%   the glyph AND the visit count, + a new goal
```

**`jev` は壁に一度も歩き込みません。**
そして `jevmemo` は —— **同じ glyph 本文に訪問回数を足しただけ**で ——
**縦方向の壁に、目をつぶって選ぶのと同じ率で歩き込みます**。

だから 19% は**読めていない**のではありません。
**情報はペイロードに入っていて、`jev` はそれを使っていました。**
**優先順位の失敗**で、ペイロードがその理由をそのまま書いています。

### b.3 memory が壁を推薦していた

壁は**立ったことがない**ので訪問回数は 0、
だから `jevmemo` がその選択肢に足す文はこうなります:

```
step north; the square there shows `-` = wall; YOU HAVE NEVER STOOD THERE
```

そして足す指示はこうです:

```
...prefer a direction that leads to ground you have not walked...
```

**壁はすべて定義上「未訪問」です。**
足した文と足したゴールの**両方が壁を指していて**、
基本ゴールの「walking into a wall achieves nothing」と**矛盾しています**。

[34 §2.4](34-roguelike.md) は 19% を
**「探索の代価」と読みました**。代価ではなく**プロンプトの矛盾**で、
書いたのは私です。

> **判断の成績を読む前に、判断に渡した文を読む。**
> ここでは結果の側からは「探索と引き換え」に見え、
> ペイロードの側からは 1 行で見えました。

## c. `swing` は尺度を測っているのか

5 段階と 9 段階を**同じリクエストで**聞きました。
これが設計の要点です ——
別 run にすると**ゲームが再生され、選ぶ手が変わり、
比べている軌跡が別の軌跡になります**。
`instructions` は同一、9 段階のうち**1 つ飛ばしの 5 つは 5 段階の文を逐語**
(`test.ts` が両方を検査)。差は**解像度だけ**。

そして算術の分も外しました: 9 段階は 0..8、5 段階は 0..4 なので、
同じ変化が**判断の前から 2 倍に読めます**。2 で割ります。

```
  spearman(five-level, nine-level rescaled) = 0.947 over 317 plies
  mean |difference| after rescaling: 0.097 on a 0..4 scale
```

順位:

```
  game        games   swing (5 levels)      swing (9, rescaled)   solver crit
                          mean [range]          mean [range]
  nim             6   0.415 [0.19..1.01]    0.470 [0.23..1.02]          0.542
  tictactoe       6   0.479 [0.32..0.63]    0.402 [0.23..0.55]          0.364
  misere          6   0.187 [0.13..0.26]    0.177 [0.14..0.26]          0.372
  connect3        6   0.350 [0.30..0.40]    0.263 [0.21..0.30]          0.069
  drift           6   0.133 [0.12..0.15]    0.122 [0.11..0.13]          0.000

  5 段階:  tictactoe > nim > connect3 > misere > drift
  9 段階:  nim > tictactoe > connect3 > misere > drift
  spearman between the two rankings: 0.900
```

**順位は動きました。** しかしそこで止めるのが間違いです ——
**入れ替わった 2 件のレンジは重なっています**
(nim [0.19..1.01] と tictactoe [0.32..0.63])。
[25](25-thresholds.md) の規律を順位に当てると:

```
  pair                       5 levels   9 levels
  tictactoe > nim             OVERLAP    OVERLAP
  nim > connect3              OVERLAP    OVERLAP
  connect3 > misere               yes    OVERLAP
  misere > drift              OVERLAP        yes
```

**隣接 4 組のうち、両方の尺度で分離しているのは 0 組。**

だから答えは「解像度依存かどうか」ではありません ——
**[35 §1](35-tension.md) の swing 順位は、そのコーパスでは確立されていない**。
ゲーム 6 本ずつでは、どの隣接ペアも並べられません。
**順位として印刷されていたものは、同点でした。**

そして 4 段階増やした分は使われていません:

```
  scale        distinct values seen   at the extremes   in the middle band
  5 levels                      145                0%                  66%
  9 levels                      192                0%                  73%
```

**両方の尺度で、極端は 0%。** 判断は
「負けている」「勝っている」を決定的には一度も言いません。
そして**細かい尺度のほうが中央に寄ります**(73% 対 66%)——
増やした 4 段階は**使われない解像度**でした。

## f. union state の形

[37 §6](37-hermes.md) が測ったのは**束ねるかどうか**で、
**どう束ねるか**ではありません。
`turn.ts` は 3 つ選択をしていて、自分のコメントにそう書いてあって、
**どれも測っていませんでした**:

| | 出荷している選択 |
| --- | --- |
| `what` | 3 つの文を**1 つに畳む** |
| `cwd` | model router が `working_directory` で持っているので**落とす** |
| 構造 | **フラット**(これは選択としてすら書いていない) |

同じ事実を 4 通りに並べ、**質問は 4 つとも同一**にしました:

```
§1 the bar
  repeats of ONE shape on one turn move an answer by sd 0.0162 (widest 0.170, 320 cells)

§2 how far each answer moves when the shape changes
  answer                          shipped   threewhats   dupcwd   nested   spread   vs noise
  tier                              0.403    0.424    0.399    0.413    0.025    1.52x <-
  tier__confidence                  0.665    0.618    0.658    0.664    0.047    2.89x <-
  underspecified                    0.599    0.620    0.603    0.607    0.021    1.29x <-
  oversized                         0.301    0.302    0.297    0.342    0.045    2.76x <-
  effort                            1.366    1.372    1.355    1.342    0.030    1.85x <-
  effort__confidence                0.598    0.598    0.598    0.568    0.030    1.87x <-
  needs_more_than_one               0.232    0.233    0.221    0.217    0.016    1.00x <-
  topology__confidence              0.709    0.718    0.702    0.727    0.025    1.56x <-
  stay_single                       0.688    0.696    0.706    0.704    0.018    1.14x <-
  big_enough                        0.344    0.339    0.337    0.339    0.008    0.48x
```

**10 個のうち 9 個が繰り返しノイズより大きく動きます。**
[37 §6](37-hermes.md) が「束ねるのは無料ではない」と言ったのと同じ形が、
**同じ束ね方の中の並べ方についても出ました**。

一番動いたのは `tier__confidence`(2.89 倍)と `oversized`(2.76 倍)。
`oversized` は **`nested` で最も動きます**(0.301 → 0.342、相対 14%)——
これは model router の**降格ガード**なので、
「入れ子にすると降格の判断が変わりうる」ということです。

**ただし決定は 1 件も動きません:**

```
  >> 0 of 8 turns pick a different topology under a different shape.
```

そして出荷している形が**一番安い**:

```
  shape        input tokens   vs shipped   ms
  shipped              1292            0     173
  threewhats           1346          +54     169
  dupcwd               1313          +21     159
  nested               1394         +103     175
```

つまり:**3 つの選択は測らずに決めたものだったが、測ったら正しかった。**
ただし正しさの理由は「答えが変わらないから」ではなく
**「答えは変わるが決定は変わらず、しかも一番安いから」**です。
[37 §6](37-hermes.md) の教訓のとおり ——
**動いた答えが問題になるのは閾値の近くだけ**。

## 正直な限界

- **b の因果は示していません。** 「memory が壁を推薦している」は
  ペイロードの矛盾と、`jev`(壁 100% 回避)対 `jevmemoraw`(縦 −4%)の
  対比からの読みです。**矛盾を取り除いたアームとの比較**が
  宿題 a の run に入っていて、そのアームが出荷されました(§a.3b)。
- **b の位置の問いは依然未回答。** `StepRow` に `x`/`y` を足したので
  次の run からは無料ですが、**この記録では分かりません**。
- **c の 6 本ずつは少なすぎます。** それがまさに c の結論ですが、
  **「では何本なら並べられるか」は測っていません**。
  レンジの重なりから逆算する話で、それは別の実験です。
- **c は `jev` アームだけ**です(`jevterse` は再実行していない)。
- **f の 8 ターンは私が書いたもの**で、ラベルはありません。
  測ったのは「答えが動くか」で、**どの形が正しいかではありません** ——
  動いた答えのうちどれが**正しい方向に**動いたかは、
  正解が無いので言えません。
- **f の 4 形は私が選んだ 4 通り**です。`turn.ts` が
  実際にした 3 つの選択に対応させましたが、
  ありうる並べ方は他にもあります。
- **f の shape 差は絶対値では小さい**(0.008〜0.047)。
  ノイズ比で 2.89 倍でも、`tier` が 0.403 から 0.424 に動くのは
  **cutoff が間にあるときだけ**問題になります。
- 宿題 **i / j**(抽象的要約の捏造)は
  **生成モデルの資格情報が無いので着手していません**
  ([39 §7](39-compact-ranking.md))。
