(`jevmemo` に渡す訪問回数のために必要)、

**2. それでも b は答えが出ました。しかも聞かれたより良い答えが。**
`jevmemo` の却下 19% は**地図の縁でも列の読み違いでもなく、
自分のプロンプトの矛盾**でした ——
**壁は必ず「まだ立ったことがない」**ので、
memory が付ける文は壁に対して
「you have never stood there」と読み、
`MEMO_GOAL` は「歩いていない方を選べ」と言う。
**memory が壁を推薦している。**

**3. c の答えは「ランキングが最初から立っていなかった」。**
5 段階と 9 段階を**同じリクエストで**聞いて、順位は動きました

しかし**隣接ペア 4 組のうち、両方の尺度で分離しているのは 0 組**。

解像度の問題ではなく、**ゲーム 6 本ずつでは並べられない**。

**4. f は「形は答えを動かすが、決定は動かさない」。**
同じ事実を 4 通りに並べて、**10 個の答えのうち 9 個が
繰り返しノイズより大きく動きました**(1.00〜2.89 倍)。
ただし **topology の決定は 8 件すべてで不変**。

## b. `jevmemo` は何を却下していたのか

### b.1 まず前提の訂正

```
  steps in the record: 2916
  steps carrying a screen position: 0
```

宿題が「リクエスト 0 件で分かる」と書いた根拠は**私の記録についての記憶違い**でした。
位置は**計算されていて、記録されていない**。
`StepRow` に `x`/`y` を足したので**次の run からは無料で分かります**が、
既存の記録では分かりません。

### b.2 答えられる半分 —— そして方向は記録に入っている

「地図の縁」と「列の読み違い」は**方向について別の予測をします**:

- **壁はどの向きでも壁。** 縁なら南北と東西に等しく出るはず。
- **列の読み違いは方向特異的。** [34 §1.1](34-roguelike.md) が測った失敗は
  **縦方向**(`@` の**行**を読み違える)。行が分からないなら北と南を間違え、
  西と東については何も間違えない。

そして決定的な事実 —— **`actions.ts` は 8 方向を必ず全部出します**、
壁に向かう手も含めて。各選択肢の本文が
「the square there shows `-` = wall」と**書いてあります**。
だから `random`(一様に選ぶ)は**ダンジョン自身の幾何**を測っていて、
他のアームはそれに対して採点できます:

```
  policy      walls avoided: vertical   horizontal   what the arm was given
  greedy                       100%          60%   a hand-written heuristic
  jev                          100%          98%   each square's glyph, in the option text
  jevbare                       13%          92%   the direction name ONLY; map from the screen
  jevmemo                       -4%          73%   the glyph AND the visit count, + a new goal
```

**`jev` は壁に一度も歩き込みません。**
そして `jevmemo` は —— **同じ glyph 本文に訪問回数を足しただけ**で ——
**縦方向の壁に、目をつぶって選ぶのと同じ率で歩き込みます**。

だから 19% は**読めていない**のではありません。
**情報はペイロードに入っていて、`jev` はそれを使っていました。**
**優先順位の失敗**で、ペイロードがその理由をそのまま書いています。

### b.3 memory が壁を推薦していた

壁は**立ったことがない**ので訪問回数は 0、
だから `jevmemo` がその選択肢に足す文はこうなります:

```
step north; the square there shows `-` = wall; YOU HAVE NEVER STOOD THERE
```

そして足す指示はこうです:

```
...prefer a direction that leads to ground you have not walked...
```

**壁はすべて定義上「未訪問」です。**
足した文と足したゴールの**両方が壁を指していて**、
基本ゴールの「walking into a wall achieves nothing」と**矛盾しています**。

[34 §2.4](34-roguelike.md) は 19% を
**「探索の代価」と読みました**。代価ではなく**プロンプトの矛盾**で、
書いたのは私です。

> **判断の成績を読む前に、判断に渡した文を読む。**
> ここでは結果の側からは「探索と引き換え」に見え、
> ペイロードの側からは 1 行で見えました。

## c. `swing` は尺度を測っているのか

5 段階と 9 段階を**同じリクエストで**聞きました。
これが設計の要点です ——
別 run にすると**ゲームが再生され、選ぶ手が変わり、
比べている軌跡が別の軌跡になります**。
`instructions` は同一、9 段階のうち**1 つ飛ばしの 5 つは 5 段階の文を逐語**
(`test.ts` が両方を検査)。差は**解像度だけ**。

そして算術の分も外しました: 9 段階は 0..8、5 段階は 0..4 なので、
同じ変化が**判断の前から 2 倍に読めます**。2 で割ります。

```
  spearman(five-level, nine-level rescaled) = 0.947 over 317 plies
  mean |difference| after rescaling: 0.097 on a 0..4 scale
```

順位:

```
  game        games   swing (5 levels)      swing (9, rescaled)   solver crit
                          mean [range]          mean [range]
  nim             6   0.415 [0.19..1.01]    0.470 [0.23..1.02]          0.542
  tictactoe       6   0.479 [0.32..0.63]    0.402 [0.23..0.55]          0.364
  misere          6   0.187 [0.13..0.26]    0.177 [0.14..0.26]          0.372
  connect3        6   0.350 [0.30..0.40]    0.263 [0.21..0.30]          0.069
  drift           6   0.133 [0.12..0.15]    0.122 [0.11..0.13]          0.000

  5 段階:  tictactoe > nim > connect3 > misere > drift
  9 段階:  nim > tictactoe > connect3 > misere > drift
  spearman between the two rankings: 0.900
```

**順位は動きました。** しかしそこで止めるのが間違いです ——
**入れ替わった 2 件のレンジは重なっています**
(nim [0.19..1.01] と tictactoe [0.32..0.63])。
[25](25-thresholds.md) の規律を順位に当てると:

```
  pair                       5 levels   9 levels
  tictactoe > nim             OVERLAP    OVERLAP
  nim > connect3              OVERLAP    OVERLAP
  connect3 > misere               yes    OVERLAP
  misere > drift              OVERLAP        yes
```

**隣接 4 組のうち、両方の尺度で分離しているのは 0 組。**

だから答えは「解像度依存かどうか」ではありません ——
**[35 §1](35-tension.md) の swing 順位は、そのコーパスでは確立されていない**。
ゲーム 6 本ずつでは、どの隣接ペアも並べられません。
**順位として印刷されていたものは、同点でした。**

そして 4 段階増やした分は使われていません:

```
  scale        distinct values seen   at the extremes   in the middle band
  5 levels                      145                0%                  66%
  9 levels                      192                0%                  73%
```

**両方の尺度で、極端は 0%。** 判断は
「負けている」「勝っている」を決定的には一度も言いません。
そして**細かい尺度のほうが中央に寄ります**(73% 対 66%)——
増やした 4 段階は**使われない解像度**でした。

## f. union state の形

[37 §6](37-hermes.md) が測ったのは**束ねるかどうか**で、
**どう束ねるか**ではありません。
`turn.ts` は 3 つ選択をしていて、自分のコメントにそう書いてあって、
**どれも測っていませんでした**:

| | 出荷している選択 |
| --- | --- |
| `what` | 3 つの文を**1 つに畳む** |
| `cwd` | model router が `working_directory` で持っているので**落とす** |
| 構造 | **フラット**(これは選択としてすら書いていない) |

同じ事実を 4 通りに並べ、**質問は 4 つとも同一**にしました:

```
§1 the bar
  repeats of ONE shape on one turn move an answer by sd 0.0162 (widest 0.170, 320 cells)

§2 how far each answer moves when the shape changes
  answer                          shipped   threewhats   dupcwd   nested   spread   vs noise
  tier                              0.403    0.424    0.399    0.413    0.025    1.52x <-
  tier__confidence                  0.665    0.618    0.658    0.664    0.047    2.89x <-
  underspecified                    0.599    0.620    0.603    0.607    0.021    1.29x <-
  oversized                         0.301    0.302    0.297    0.342    0.045    2.76x <-
  effort                            1.366    1.372    1.355    1.342    0.030    1.85x <-
  effort__confidence                0.598    0.598    0.598    0.568    0.030    1.87x <-
  needs_more_than_one               0.232    0.233    0.221    0.217    0.016    1.00x <-
  topology__confidence              0.709    0.718    0.702    0.727    0.025    1.56x <-
  stay_single                       0.688    0.696    0.706    0.704    0.018    1.14x <-
  big_enough                        0.344    0.339    0.337    0.339    0.008    0.48x
```

**10 個のうち 9 個が繰り返しノイズより大きく動きます。**
[37 §6](37-hermes.md) が「束ねるのは無料ではない」と言ったのと同じ形が、
**同じ束ね方の中の並べ方についても出ました**。

一番動いたのは `tier__confidence`(2.89 倍)と `oversized`(2.76 倍)。
`oversized` は **`nested` で最も動きます**(0.301 → 0.342、相対 14%)——
これは model router の**降格ガード**なので、
「入れ子にすると降格の判断が変わりうる」ということです。

**ただし決定は 1 件も動きません:**

```
  >> 0 of 8 turns pick a different topology under a different shape.
```

そして出荷している形が**一番安い**:

```
  shape        input tokens   vs shipped   ms
  shipped              1292            0     173
  threewhats           1346          +54     169
  dupcwd               1313          +21     159
  nested               1394         +103     175
```

つまり:**3 つの選択は測らずに決めたものだったが、測ったら正しかった。**
ただし正しさの理由は「答えが変わらないから」ではなく
**「答えは変わるが決定は変わらず、しかも一番安いから」**です。
[37 §6](37-hermes.md) の教訓のとおり ——
**動いた答えが問題になるのは閾値の近くだけ**。

## 正直な限界

- **b の因果は示していません。** 「memory が壁を推薦している」は
  ペイロードの矛盾と、`jev`(壁 100% 回避)対 `jevmemo`(縦 −4%)の
  対比からの読みです。**矛盾を取り除いたアームとの比較**が
  宿題 a の run に入っています(`jevmemofix`)。
- **b の位置の問いは依然未回答。** `StepRow` に `x`/`y` を足したので
  次の run からは無料ですが、**この記録では分かりません**。
- **c の 6 本ずつは少なすぎます。** それがまさに c の結論ですが、
  **「では何本なら並べられるか」は測っていません**。
  レンジの重なりから逆算する話で、それは別の実験です。
- **c は `jev` アームだけ**です(`jevterse` は再実行していない)。
- **f の 8 ターンは私が書いたもの**で、ラベルはありません。
  測ったのは「答えが動くか」で、**どの形が正しいかではありません** ——
  動いた答えのうちどれが**正しい方向に**動いたかは、
  正解が無いので言えません。
- **f の 4 形は私が選んだ 4 通り**です。`turn.ts` が
  実際にした 3 つの選択に対応させましたが、
  ありうる並べ方は他にもあります。
- **f の shape 差は絶対値では小さい**(0.008〜0.047)。
  ノイズ比で 2.89 倍でも、`tier` が 0.403 から 0.424 に動くのは
  **cutoff が間にあるときだけ**問題になります。
- 宿題 **i / j**(抽象的要約の捏造)は
  **生成モデルの資格情報が無いので着手していません**
  ([39 §7](39-compact-ranking.md))。
