# 22. 具体的な「良いコード」の指標を与える

[21](21-eslint-plugin-jev.md) は曖昧な 1 問(「レビューでどれだけ押し返すか」)で
**12 バグ中 5 個**しか捕まえられず、**落とした 6 個は全部同じ型**だった ——
「特定の API が、コードが仮定しているとおりには振る舞わない」。

[01 §5](01-shell-risk.md#5-rubric-は書いた軸しか答えない) は
「rubric は書いた軸しか答えない」と言っている。ならあの 6 個は
**見えなかったのか、聞かれていなかったのか**。**8 つの具体的な指標に名前を付けて**測った。

再現:

```bash
cd experiments/eslint-plugin-jev && npm install
npm test                                              # 57 件、API 不要
npm run truth                                         # 17 バグ全部をコード実行で証明、API 不要
npm run replay:criteria                               # 記録から全数値を再計算、API 不要
TYPESAFEAI_API_KEY=... npm run criteria -- --repeat 3  # 4 rubric × 3 = 168 req、$0.030
TYPESAFEAI_API_KEY=... npm run warm -- --rubric full && npm run lint
```

---

## 結論(先に)

**捕まる数は増える。指摘に名前が付く。ただし「指標を書けば当たる」ではなかった。**

3 つ、順に重要:

1. **指標を名前で聞くと 33/51 → 41/51。** 誤検出は同じ 3/138。
   そして指摘が `median matches api_default (0.35)` のように**名前で返る**。
   `score 1.94/3` から、直せる情報になった。
2. **効いたのは指標そのものより「指標ごとの閾値」だった。**
   8 指標を**共通の閾値 0.80** で見ると 13/36 しか拾わない。
   指標ごとに閾値を引くと **24/36**、誤検出は同じ 0。
   理由は分布で、`unit_or_arithmetic` は自クラスに **0.94** と答えるのに
   `api_default` は **0.20** しか出さない —— それでも AUC 0.80 で正しく順序づけている。
   **確率のスケールが指標ごとに違う。**
3. **[21](21-eslint-plugin-jev.md) が落とした 6 個のうち、戻ったのは 2 個だけ。**
   `.sort()` の比較関数なし(0.32)と `setUTCMonth` の桁溢れ(0.27)は戻った。
   `splice(at)` の引数不足は **0.12**、`/g` なしは **0.09**、`await` 忘れは 0.22。
   **ちょうど正しい問いを名指しで投げて、自信をもって「いいえ」と答える。**

そして代償が 1 つ、これが一番効く知見:

> **名前の正しさは、閾値を下げると壊れる。**
> 共通閾値 0.80 で発火したときは名前が **13/13(100%)**正しい。
> 拾う数を増やすために閾値を下げると **20/26(77%)**に落ちる。
> **再現率は、名前の信頼性そのもので買っている。**

## 1. 8 つの指標

`src/judge.mjs` の `ATOMS`。それぞれ独立した noul で、true/false の criteria 付き:

| 指標 | 何を聞いているか |
| --- | --- |
| `api_default` | ライブラリ呼び出しが、渡した引数では持たない挙動に依存している |
| `unhandled_async` | promise の失敗か値が、握られないまま逃げている |
| `boundary` | 空・先頭・末尾・範囲外・ゼロサイズで間違う |
| `swallows_failure` | 呼び出し側が知る必要のある失敗を捨てている |
| `name_mismatch` | 名前と引数だけ読んだ人が誤解する |
| `lost_update` | 共有状態を read-modify-write して、間に中断点がある |
| `unescaped_composition` | 後でパースされる文字列に、未エスケープの値を差し込んでいる |
| `unit_or_arithmetic` | 割合・金額・時間単位・添字のスケールか演算が違う |

**この 8 つはコーパスの欠陥クラスを見て書いた。** つまり**当てはめた指標**で、
測っているのは**天井**(クラスを名指しすれば見つかるか)であって汎化ではない。

だから**先に、この 8 つに入らないクラスのバグを 5 個**作って保留した
(`ranges.js`・`pool.js`。指標より先に書いたので、指標をこれに合わせられない):

```
pool.js#withConnection   try/finally が無く、throw で接続がリークする
pool.js#settingsFor      無効化のないキャッシュ。変更後も古い値を返す
pool.js#reachable        visited 集合が無く、循環でスタックが溢れる
ranges.js#mergeRanges    結果を組み立てて return を忘れている
ranges.js#modeFlags      switch の break 漏れで read が read+write になる
```

コーパスは **68 関数 / 14 ファイル** — bug 17(名前付き 12 + 保留 5)、
smell 5、nearmiss 7、clean 39。**17 バグ全部にプローブが付いていて、
`npm run truth` がコードを実行して壊れていることを確定させる**
([21 §10](21-eslint-plugin-jev.md#10-正直な限界) の方針のまま)。

### 4 つの聞き方

| rubric | 質問/関数 | 何を聞くか |
| --- | --- | --- |
| `vague` | 2 | [21](21-eslint-plugin-jev.md) の形。レビュー行動の score + 汎用 noul 1 個 |
| `checklist` | 2 | 同じ 2 問。ただし **score の instructions に 8 指標を列挙**する |
| `atoms` | 8 | **8 指標を 8 つの noul** として聞く。score も汎用 noul も無し |
| `full` | 10 | score + 汎用 noul + 8 指標。**全部 1 リクエスト**に入る |

`checklist` があるのは切り分けのため —— 改善したとき
「何が問題かを言うのが効いた」のか「別々に聞くのが効いた」のかを分ける。
**同じ情報を 1 問に入れるか 9 問に分けるか**の違いだけ。

質問キーは `a3-007` のような不透明キーにしてある。`api_default-007` にすると、
応答マップに指標名が載って**分類体系が 2 回ワイヤーに出る**。

## 3. 落とした 6 個のうち、戻ったのは 2 個

**これが本題の答え。** [21](21-eslint-plugin-jev.md) の 6 つの見逃しに、
**その欠陥クラス専用の指標を名指しで投げた**結果:

| [21](21-eslint-plugin-jev.md) の見逃し | 投げた指標 | 自クラスへの答え | 戻った? |
| --- | --- | --- | --- |
| `.sort()` に比較関数が無い(`median`) | `api_default` | **0.32** | **戻った** |
| `setUTCMonth` が桁溢れ(`addMonths`) | `api_default` | **0.27** | **戻った** |
| `await` 忘れ(`retry`) | `unhandled_async` | 0.22 | 戻らない |
| `splice(at)` の引数不足(`EventBus#off`) | `api_default` | **0.12** | 戻らない |
| `/g` が無い(`slugify`) | `api_default` | **0.09** | 戻らない |
| LRU なのに順序を更新しない(`LruCache#get`) | `name_mismatch` | **0.11** | 戻らない |

**3 回とも同じ。** 0.09 や 0.11 は迷いではなく、
**ちょうど正しい質問に対する自信のある「いいえ」**。

> **[01 §5](01-shell-risk.md#5-rubric-は書いた軸しか答えない) には限界がある。**
> 「rubric は書いた軸しか答えない」は真だが、**軸を書けば答えが来るとは限らない**。
> 観察そのものができないなら、名指ししても出てこない。
> [21 §3](21-eslint-plugin-jev.md#3-結果--捕まえたものと落としたもの) の
> 「契約の齟齬は捕まえ、API の誤用は落とす」は**質問設計の問題ではなかった**。

`api_default` が自クラス 12 判定中 6 を拾ったのは、閾値を 0.22 に下げた後の話(→ §4)。

## 4. 一番効いたのは指標ではなく「指標ごとの閾値」

8 指標を**共通の閾値 0.80** で見ると、半分が一度も発火しない:

| 指標 | 自クラス @0.80 | 誤検出 @0.80 | 自クラス平均 | clean 平均 | **AUC(自クラス vs clean)** |
| --- | --- | --- | --- | --- | --- |
| `unit_or_arithmetic` | 3/3 | 0/138 | 0.94 | 0.05 | 1.00 |
| `unescaped_composition` | 3/3 | 0/138 | 0.94 | 0.03 | 1.00 |
| `lost_update` | 3/3 | 0/138 | 0.94 | 0.08 | 1.00 |
| `boundary` | 3/3 | 0/138 | 0.82 | 0.24 | 1.00 |
| `swallows_failure` | 1/3 | 0/138 | 0.79 | 0.12 | 1.00 |
| `name_mismatch` | **0/6** | 0/138 | 0.39 | 0.17 | 0.67 |
| `unhandled_async` | **0/3** | 0/138 | 0.22 | 0.06 | **0.92** |
| `api_default` | **0/12** | 0/138 | 0.20 | 0.10 | **0.80** |

**`api_default` と `unhandled_async` は死んでいない、冷たいだけ。**
一度も 0.80 に届かないのに、**AUC 0.80 / 0.92 で自クラスを clean の上に並べている**。
検出の問題ではなく**校正の問題**で、道具は**指標ごとの閾値**になる。

各指標について「clean に 1 件も誤検出しない範囲で最大に拾う閾値」を当てはめると:

| 指標 | 閾値 | 自クラス | 共通 0.80 では |
| --- | --- | --- | --- |
| `api_default` | **0.22** | **6/12** | 0/12 |
| `unescaped_composition` | 0.23 | 3/3 | 3/3 |
| `unit_or_arithmetic` | 0.28 | 3/3 | 3/3 |
| `swallows_failure` | 0.38 | **3/3** | 1/3 |
| `name_mismatch` | 0.47 | **3/6** | 0/6 |
| `boundary` | 0.55 | 3/3 | 3/3 |
| `unhandled_async` | 0.57 | 0/3 | 0/3 |
| `lost_update` | 0.73 | 3/3 | 3/3 |

**24/36 対 13/36**、誤検出は同じ。閾値は 0.22 から 0.73 まで**3 倍以上**開いている。

> **同じ形の質問を並べても、確率は同じ尺度で返ってこない。**
> [04 §2](04-agent-built-prompts.md#2-原因は設計ではなく閾値だった) の
> 「質問はエージェント、閾値はデータ」を**ゲート単位ではなく質問単位**で適用する必要がある。
> `unhandled_async` は AUC 0.92 なのに 0 件 —— **順序は完璧で、値が全部低い。**

だから合成も「最大値」ではなく**自分の閾値からの超過率**で選ぶ
(`firedAtom`)。`api_default 0.44`(閾値 0.22、2.0 倍)は
`lost_update 0.74`(閾値 0.73、1.01 倍)より強い主張。

**この閾値は 68 関数に当てはめた値**で、各指標の「clean の最大値 + 0.01」——
つまり**誤検出の境界そのもの**に置いてある。だから他のコードでは誤検出が出る。
実際、記録とは別の新しい 1 回を走らせたら **`dedupeSlugs`(clean)が
`unescaped_composition` 0.24 対 閾値 0.23 で発火**した。
当てはめが隠していた分散がそのまま出た形で、`criterionAt` がオプションなのはこのため。

## 5. 名前の正しさは、閾値を下げると壊れる

指標を使う理由は**名前が付くこと**だけ。その名前がどれだけ当たるか:

| 発火の条件 | 発火した数 | 名前が正しい |
| --- | --- | --- |
| 共通閾値 0.80 | 13/36 | **13/13(100%)** |
| 指標ごとの閾値 | 26/36 | **20/26(77%)** |
| 閾値を無視して argmax | 36/36 | 20/36(56%)、top-2 で 29/36 |

**高い確率で発火したときの名前は完全に信頼できる。**
拾う数を増やすために閾値を下げると、名前は 77% に落ちる。

新しい 1 回の実測でも見える。`compareTokens`(空トークンで認証が通る)は
`swallows_failure` 0.53 で発火した —— **検出は正しく、名前は間違っている**。
`saveAll`(書き込み失敗を握り潰す)は `unescaped_composition` 0.53。

> **再現率と名前の信頼性は同じ通貨で買っている。**
> 「何が悪いか」を言わせたいなら高い閾値、
> 「見逃したくない」なら低い閾値 —— **両方は取れない**。
> `criterionAt` を上げると指摘は減るが、残った指摘の名前は当たる。

補足: `covers`(どの指標が拾うべきか)も**こちらの意見**。
`compareTokens` を `name_mismatch` に割り当てたが、空入力の扱いなので
`boundary` でも筋は通る。§5 の分母はこの割り当てに依存している。

## 6. 列挙していないクラスには穴が空く

保留した 5 個(§1)での再現率:

| rubric | 名前付き 12 クラス | 保留 5 クラス |
| --- | --- | --- |
| `vague`(汎用 noul のみ) | 18/36 | **15/15** |
| `atoms`(8 指標のみ) | 25/36 | **11/15** |
| `full`(両方) | 26/36 | **15/15** |

**`atoms` は名前付きクラスで勝ち、保留クラスで負ける。**
[01 §4](01-shell-risk.md#4-分解は万能ではない) の
「列挙し忘れた脅威クラスに穴が空く」が、そのまま数字で出た。
そして**穴を埋めるのは汎用質問**で、`full` が両方 100% を取り戻している。

面白いのは、指標が**隣の名前に着地して**保留バグを拾うこと:

```
ranges.js#mergeRanges  (return 忘れ)      -> name_mismatch 0.76
pool.js#settingsFor    (古いキャッシュ)   -> lost_update   0.83
pool.js#withConnection (リーク)           -> unhandled_async 0.63
```

`return` を忘れた関数は確かに名前と食い違う。**名前は正確ではないが、無意味でもない。**

> **原子質問は汎用質問の代わりではなく、上乗せ。**
> [01 §4](01-shell-risk.md#4-分解は万能ではない) の教訓の、別ドメインでの再確認。

## 7. チェックリストを instructions に入れると、校正になるだけ

`checklist` arm は 8 指標を score の instructions に列挙する。同じ情報、1 問。

**検出は増えなかった**(33/51 → 31/51)。動いたのは**スケール全体**:

| | clean | nearmiss | smell | bug |
| --- | --- | --- | --- | --- |
| `vague` の score | 0.83 | 1.14 | 1.41 | 1.56 |
| `checklist` の score | **0.65** | **0.89** | 1.22 | 1.43 |

**全クラスが下がった**(clean が一番大きく −0.18)。
「何が問題に数えられるか」を列挙すると**基準が厳しくなる**ので、
同じコードの score が下がる。分離は少し良くなり(bug−clean が 0.73 → 0.78)、
誤検出は 3 → 2 に減るが、**新しい検出は 1 件も生まれない**。
そして**トークンは 81% 増える**(27k → 50k)。

> **指標を「言う」のと「別々に聞く」のは別のこと。**
> instructions に列挙するのは rubric の再校正で、
> 検出を増やすには**問いを分ける**必要がある(そして名前が付くのも分けたときだけ)。

## 9. 正直な限界

- **8 指標はコーパスを見て書いた。** §2〜5 は**天井の測定**で、汎化の測定ではない。
  汎化を測っているのは保留 5 クラスの列(§6)だけ。
- **保留 5 個は、たまたま `vague` に易しかった。** 5/5 を素で拾っている。
  「return 忘れ」「break 漏れ」は
  [21 §3](21-eslint-plugin-jev.md#3-結果--捕まえたものと落としたもの) の言う
  **契約の齟齬側**で、落ちる「API の誤用」側ではなかった。
  **穴の深さはこの 5 個では測れていない** —— 測るには
  「名前を付けていない、かつ API 知識が要る」クラスが必要で、それは作りにくい。
- **閾値は 68 関数に当てはめた値。** 誤検出の境界そのものに置いてあるので、
  他のコードでは誤検出が出る(§4 で実際に出た)。**最初に再校正すべき数字**。
- **`covers` はこちらの意見。** §5 の「名前が正しい」の分母はこの割り当て依存。
- **指標を落として良いかは測っていない。** `api_default` と `unhandled_async` は
  共通閾値では 0 件だが AUC は高いので、**落とすと自クラスの順序情報を失う**。
  残してある。
- **3 回では `name_mismatch` の 0.67 と 1.00 の差は確定しない。**
  自クラス 6 判定(2 関数 × 3)しかない。
- **smell 5 件は主指標から外してある。** 意見なので
  ([21](21-eslint-plugin-jev.md) と同じ)。ただし `full` は smell にもよく発火する
  (`loadConfig` → `swallows_failure` 0.57 など)。指摘としては妥当だが数えていない。

## 10. この実験で確定したこと

1. **具体的な指標を名前で聞くと、捕まる数は増えて指摘に名前が付く。**
   33/51 → 41/51、誤検出は同じ 3/138。`score 1.94/3` が
   `api_default (0.35)` になる。
2. **[21](21-eslint-plugin-jev.md) が落とした 6 個のうち戻ったのは 2 個。**
   残り 4 個は**ちょうど正しい問いに 0.09〜0.22 で「いいえ」**と答える。
   質問設計の問題ではなく、観察できていない。
3. **同型の質問でも確率のスケールは指標ごとに違う。**
   自クラス平均が 0.20 から 0.94 まで開き、共通閾値 0.80 は
   AUC 0.80/0.92 の 2 指標を丸ごと捨てる。**閾値は質問ごとに引く。**
4. **再現率と「名前の正しさ」は同じ通貨で買う。**
   0.80 で発火 → 名前 100%、指標ごとの閾値まで下げる → 77%。
5. **原子質問は汎用質問の上乗せで、代わりではない。**
